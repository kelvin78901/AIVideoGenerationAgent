## 设计要点

### 产物和版本（SPEC 4.2）
- 新表 `product`、`product_version`（只追加）、`dependency`、`gate_decision`。**版本是唯一真相**；`bible_entity`、`suggestion`、`episode`、`beat`、`scene`、`script_line` 是「已采纳版本」的物化表，可以随时从版本重建（有测试：全部重建后行完全一样）。
- **id 在出版本时定**，写进 `payload_json`：重跑时和它出发时的已采纳版本逐项比对（设定按类别 + 名字 / 别名，分集按序号，场按序号，剧本行在同一场里按文字相似度），对上的沿用 id；编辑出的版本保留原 id。物化只按 id upsert；版本里没有的行标 `retired`，不硬删（下游以后挂在行上的产物，比如配音、镜头，外键不断）。
- **当前和采纳**（硬规则 5）：还没采纳过时，第一个成功的版本自动采纳；之后的重跑只变「当前」，要用户点「采纳」。当前 ≠ 采纳时，`GET /script`、`/bible`、`/suggestions` 用同一个纯函数从当前版本的 payload 算出来（只读，标出「未采纳」）。用户手改（改设定、拖节拍、改剧本行）从当前版本出一个 `edit` 版本并采纳。组件只读上游的已采纳 payload，不读物化表。
- 有任务在跑或排队的产物，编辑和影响预览返回 409 `product_busy`。
- **建议的决定不进版本**：单独一张 `suggestion_decision`（状态、重写后的文字、要求、重写用的模型），重跑后按 id 带过去。补全产物的「有效哈希」只算已采纳的建议（id、最终文字、锚点），待定 / 忽略的改动不让分集变旧。剧本里来自补写的行，出处写 `{source_id: "sug:<id>"}`。
- **依赖按切片算哈希**：组件的 `inputs()` 返回用到的切片和它们的哈希（规范化 JSON，排除 `idx`、`edited` 这类显示字段），例如剧本（第 n 集）依赖 `split` 的 `episode:<id>`、用到的设定条目、被引用段落里的已采纳补写。每个切片一行 `dependency`。**「待更新」现算**：比对切片哈希和上游已采纳版本的当前哈希，不存标志，所以改了再撤销会自动变回不旧。只算直接依赖；更下游的在影响预览里作为 `optional` 行列出。
- 闸门（小说、剧本）确认时把相关产物的有效哈希写进 `gate_decision.product_hashes_json` 并锁定。之后改已确认内容走 `/impact/preview` → `/impact/apply`，直接改返回 409 `locked`。**改已确认内容时影响预览至少有一行「已确认的 X 会改成新内容」**，保证弹窗总会出现（M2 后端里剧本还没有下游；示例剧集的镜头、关键帧这些下游行由 MSW 叠加）。小说闸门的 `scope_id` 前端传的是集 id，后端换成剧集。

### 组件和提示词（SPEC 5、8）
- `pipeline/component.py`：协议（`inputs / compile_prompt / output_schema / run / estimate`）+ 注册表；`product.run` 任务（队列按模型：`api:<provider>` 或 `gpu`）。结构化输出用 Pydantic 校验，失败带着错误重试一次，仍失败任务失败、原始输出存 blob 供查看。
- `prompts/compiler.py` + Jinja2 模板 `prompts/templates/<component>/<family>.j2`（先写 `default`）。**编译层只放指令**，原文、设定这些数据块发送时再拼；实际发送的完整提示词存成 blob 挂在版本上。手改编译层不会替换数据块。分集和剧本模板参考上游 `skills/0xsline-short-drama/references/`（钩子、节奏）。
- **原文按段编号**（全书连续 `[P12]`），模型只引用段号，后端换成字符区间 `{source_id, start, end}`。
- **长小说**：设定提取按章节分块，每块不超过兜底链里最小上下文的 60%（`providers.yaml` 补 `max_context`，本地 Ollama 要传 `num_ctx`）；逐块抽取后按名字 / 别名确定性合并，疑似同一人的交给 LLM 判定，结果作为「合并建议」等用户确认。提取同时给每章一段摘要，分集规划用摘要 + 设定 + 已采纳补写；剧本化每集只带本集节拍和它们引用的段落。分块结果按（提示词哈希、模型）缓存，重试或重启续跑不重复花钱。
- 每个组件设合理的 `max_tokens`（Mock 的估价默认 800 输出 token，剧本会低估）。
- 流式：OpenAICompat 的增量转成 `job.updated` 的 `progress: {chars}`，RunBar 显示「已生成 N 字」。

### Mock
- `ModelRequest` 加 `meta`（组件、任务，不发给厂商）。Mock 按（组件，任务）找应答器：剧本有 `run`、`rewrite_line`、`rewrite_scene` 三种任务。应答器通过模型注册表登记，`modelhub` 不反向依赖 `pipeline`。
- 示例小说命中时返回 `tests/fixtures/demo/` 里那份示例 JSON（和种子数据共用一份）；其他小说用简单的确定性规则（按段落切集、引号里的话当台词），保证引用的段号有效。Mock 可以配成「回非法 JSON」，测重试一次的路径。

### 预算（SPEC 7.6）
- `modelhub/budget.py`：入队前 `estimate()`。超过单次上限（`per_call_cap_usd`，出厂默认 $0.50）或本集剩余预算 → 任务进 `waiting_confirm`。本集剩余 = 预算 − 已花 − 排队 / 等确认任务的预估 −（运行中任务预估 − 已花，取非负）。设定、补全、分集这三步不属于某一集，只查单次上限。
- 确认后 `job.confirmed_usd` 记下用户同意的金额（迁移），路由器的 `BudgetGuard` 允许到这个数，兜底超过就失败 `budget_exceeded`；重启续跑不再问。
- 兜底方式「先问」（`notify: ask`）：路由器抛 `NeedsConfirm`，任务进 `waiting_confirm`，确认后按兜底模型继续。
- 同步的改写建议（剧本行 / 场、补全建议的重写）超限返回 409 `over_budget {estimate_usd, limit_usd}`，前端确认后带 `confirm_budget: true` 再发。
- 前端：全局「等你确认」弹窗（监听 `/jobs` 里 `waiting_confirm` 的任务：预计花费、原因、确认 / 取消）；RunBar 上该产物显示「等你确认」。

### 和 MSW 共存
- 规则：**MSW 只处理它内存库里有的 id，其他一律放行到后端**。每做完一块就把那块的数据从 MSW 库里删掉。
- 需要合并的几处只对示例剧集 `demo` 做：`/episodes/{id}/progress`（素材、分镜、生成三步的数）、`/series/{id}/episodes`（镜头数）、闸门（novel / script 走后端，其余照旧）、影响预览（后端结果 + 示例里剧本下游的镜头、关键帧行）。这些叠加在 M3–M5 各自做完时删掉。
- 页面测试：删掉的 handler 挪成测试专用的假后端（`web/src/test/fakes/`），数据由后端导出的 JSON 生成（沿用 M1 的 `tests/api/test_web_fixtures.py` + `DRAMA_UPDATE_FIXTURES=1`），保证契约一致。
- **示例剧集**：`seed_demo()` 按块补齐（只在 Mock、只对 `demo`、只补缺的部分，所以 Kelvin 现有的库重启后也会补上）；版本历史照 MSW 示例直接插入（例如补全 v1 本地 → v2 换模型），id 和 MSW 示例一致（`demo-e1`、`demo-b2`、`c-linwan`……）。另有测试：在示例小说上真跑一遍流水线，采纳的 payload 和种子一致。新增 `drama-studio demo [--reset]`（`--reset` 删掉 `demo` 重新建，解决后端状态和刷新后复原的 MSW 对不上）。
