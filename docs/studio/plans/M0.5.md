## 背景

M0 已完成（PR #1 待合并）。11 个页面现在是空壳。Kelvin 希望在 M1 之前先把全部界面按原型做出来、用示例数据跑通，这样：界面和交互可以先看、先改；后面每个里程碑只接后端、删掉对应的假接口，不再重写界面。

现状要点：
- 前端已有：AppShell（顶栏、导航、中英、亮暗）、`api/client.ts`（`ApiError` + 错误码翻译）、`useJobs` / `useHealth` / `useModelCalls`、`useEventStream`（全局 EventSource）、`styles/tokens.css`（亮 / 暗两套 + 图表色）、7 个 shadcn 基础件、`check-i18n.ts`、ESLint 禁止 JSX 写死中文。
- 后端已实现的 `/api/v1`：`health`、`events`、`jobs`（列表 / 详情 / 取消 / 确认）、`providers`（列表 / 存删密钥 / 测试连接）、`dev/*`。其他接口都还没有。
- 原型：11 个 `.dc.html` 已经由子代理逐页读过（布局、交互、示例数据、数字）。Kelvin 的在线画布是他 claude.ai 里的 artifact「短剧工作台原型」，里面带画布运行时 `dc-runtime.js`（React + `DCLogic`），可以在本机渲染原型。

## 关键设计

### 分支
从 `m0-foundation` 切出 `m0.5-ui`（M0 还没合进 main）。每步提交后 push 到 `m0.5-ui`。M0 合并后把 `m0.5-ui` rebase 到 main，再 `gh pr create --base main`。

### 接口契约（要求 2）
- `web/src/api/schemas/<resource>.ts`：每个接口的请求和响应都写成 zod schema，TS 类型用 `z.infer` 导出。现有的 `api/types.ts`（Job、ModelCall）也挪进来。字段用 snake_case，和后端 Python 一致。
- `api()` 增加 `schema` 参数，响应先 `parse`。不符合契约时抛 `ApiError(code="bad_response", params={path, issues})`，前端翻译后显示。这样后面接真实后端时，字段对不上会立刻暴露。
- `api/hooks/<resource>.ts`：页面只通过这些 hook 取数和改数据，`api/keys.ts` 统一管 query key。组件里不写死任何数据。
- **界面文字和内容分开**：状态、类别、原因这类枚举由接口返回 code（例如 `status: "adopted"`、`reason: "face_mismatch"`），前端按 i18n 翻译。日志、提示这类句子返回 `code + params`。小说原文、剧本、提示词、人名这些是用户内容，原样显示，不翻译。
- **SPEC 9.1 增补**：9.1 缺少一些读接口，这次补上，并在 DECISIONS 和 SPEC 9.1 里各记一笔，让后端按同一份契约实现。
  - `GET /series/{id}/episodes`
  - `GET /episodes/{id}/progress`（导航徽标：已确认、7/13、3/9、待更新 N）
  - `GET /series/{id}/novel`（段落 + 已采纳的补写）
  - `GET /series/{id}/suggestions`
  - `GET /episodes/{id}/script`（场、剧本行、来源）
  - `GET /episodes/{id}/shots`、`PATCH /shots/{id}`
  - `GET /products?owner=&component=`
  - `GET /config/components`（组件定义、可选模型、预设）
  - `GET /episodes/{id}/timeline`、`PATCH` 片段和字幕、`GET /episodes/{id}/export/checks`、`POST /episodes/{id}/export`
  - `GET /sync/board?episode=`

### MSW（要求 2、4）
- 新增 `web/src/mocks/` 目录：
  - `browser.ts`：`setupWorker`，`onUnhandledRequest: "bypass"`。没有 handler 的请求（jobs、providers、health、events、dev）直接走 Vite 代理到后端。
  - `node.ts`：Vitest 用的 `setupServer`，和浏览器共用同一套 handler。
  - `handlers/<resource>.ts`，加上 `handlers/index.ts`。index 文件头放一张表：每个接口由哪个里程碑实现，实现后删掉对应的 handler。
  - `db.ts`：内存里的示例库，从 fixtures 建，测试里每个用例前 `resetDb()`。示例库里的改动（采纳、重跑、锁定等）刷新页面后就恢复初始状态。
  - `fixtures/demo/*.ts`：《雨停之前》第 1 集的全部示例数据，类型都来自 schema。
  - `public/mockServiceWorker.js`，由 `msw init` 生成，进 git。
- **默认开启**：dev 和 build 都开，设 `VITE_DEMO_DATA=0` 关掉。所有 handler 都删完后，整个 `mocks/` 一起删。
- **「示例数据」标记**：每个 MSW 响应都带 `x-drama-demo: 1` 头。`api()` 看到这个头，就在 `stores/demo.ts` 里记下当前路由。路由用过示例数据，顶栏就显示「示例数据 / Demo data」（带说明 tooltip），和现有的「Mock 模式」标记分开。`/dev/jobs` 这种只用真实接口的页面不显示。
- **模拟运行**：`POST /products/{id}/run` 在示例库里建一个任务。延迟约 1.4 秒后追加新版本，并通过 `mocks/events.ts` 发出 `product.updated` / `version.created`。首次启动页用同样的方式发 `setup.progress` / `setup.log`。为此把 `useEventStream` 的分发逻辑抽成 `api/events.ts:dispatchEvent()`，真实 SSE 和演示事件走同一条路径。以后接真实后端时，页面代码不用改。
- **一致性测试**：`fixtures/demo/consistency.test.ts` 检查跨页数字：
  - 9 个镜头时长合计 34 秒
  - 本集已花 $8.94、预计 $13.35、预算 $15
  - 42 次调用、1 次失败
  - 素材 13 项、已锁 7 项
  - 分镜 3/9、采纳 3/9
  - 质检 6 过 4 不过
  - 改画幅影响范围 $1.26 + $2.76 = $4.02
  - 剧本 12 段、AI 新增 2 段
  - 每 15 分钟一桶的花费累计到 $8.94

### 共用组件（要求 3，SPEC 16.2）
放在 `web/src/components/`，这次做成正式组件，后面的里程碑只换数据来源：

| 组件 | 要点 |
| --- | --- |
| `CostBadge` | 金额、约数、「无 API 费用」、单价、预计花费和耗时 |
| `RunBar` | 当前产物、版本、模型、本地 / API、时间、状态；改提示词 / 重跑（生成页是「再出一条」）/ 不满意换一个 ▾ / 历史 n；按钮上标预计花费 |
| `ModelSwitchMenu` | 「不满意换一个」的下拉菜单（RunBar 和 Inspector 共用） |
| `Inspector` | 组件 chips + 运行设置 / 提示词 / 历史三个标签；用 `stores/inspector.ts` 控制，RunBar 可以直接打开某个标签 |
| `ModelPicker` | 运行位置（不可用的置灰并写明原因）、API 服务（前 6 个 + 更多供应商 N）、本地模型、自动兜底（开关、触发条件、兜底到）、单次上限；每个字段标出值来自哪一级（SPEC 7.1） |
| `PromptEditor` | 意图层；编译层预览 / 直接改；改过后标「已手动修改编译层」，可恢复自动编译；保存并重跑 / 只保存 |
| `VersionHistory` | 版本列表；设为当前、采纳这一版（同一产物只能采纳一个） |
| `ImpactDialog` | 受影响的素材、分镜、关键帧、视频和预计花费；三个选项：只标记 / 自动重跑（显示花费）/ 撤销。两种形态：`inline`（剧本、规格两页照原型嵌在页面里）和 `modal` |
| `GateButton` | 页头的「确认……，进入下一步」；调用闸门接口后跳到下一步，确认后可以重新打开 |

另外几个通用件：`PageHeader`、`StatusBadge`、`SegmentedControl`、`ChipToggle`、`MediaThumb`（按成片规格画 9:16 / 16:9 占位帧，内容由数据决定）、`EmptyState`。

### Playwright（要求 5）
- `web/playwright.config.ts` 的 webServer 同时起两个服务：后端用 `uv run drama-studio dev`，带临时 `DRAMA_HOME`、`DRAMA_MOCK=1`、独立端口；Vite 用独立端口，`DRAMA_BACKEND_URL` 指向这个后端。
- 测试分两类：
  - `e2e/smoke.spec.ts` 进 CI。逐页检查：
    - 能打开
    - 没有 console error 和 `bad_response`
    - 「示例数据」标记出现
    - 中英切换后文字变化
    - 四个按钮能产生新版本
  - `e2e/shots.spec.ts` 用 `pnpm shots [page]` 跑，不进 CI。宽度 1440 截整页，中文亮色、中文暗色各一张，存成 `docs/studio/reports/ui/<page>.light.jpg` / `<page>.dark.jpg`（JPEG 控制仓库体积）。英文截图按需生成，不进 git。
- **原型截图**：读 artifact「短剧工作台原型」，取 `dc-runtime.js`，放进 scratchpad 当 `support.js`。在本机起一个静态服务渲染 `docs/studio/prototype/*.dc.html`，用 Playwright 按画板宽度截图，存到 `docs/studio/reports/ui/prototype/<page>.jpg`。运行时只放 scratchpad，不进仓库。如果本地渲染不对，就改用 Chrome 扩展打开在线画布截图（到时候需要你在浏览器里登录）。
- `docs/studio/reports/ui/README.md` 是对照表：每页一行，三列是原型 / 实现亮色 / 实现暗色，加一列「有意的差异」。里程碑报告引用这张表。
