**盘点（2026-10-26）**

后端已经有的：

## 设计要点

### 工作流库（SPEC 6.4.2 / 6.4.4 / 6.4.5）

- 新表 `comfy_workflow`（按 SPEC 4 的列：id, slug, model_key, name, tier, source, dir, file_sha256, bindings_json, deps_json, caps_json, check_json, trial_json, created_at, updated_at）。仓库 `workflows/<slug>/` 和用户 `~/.drama-studio/workflows/<slug>/` 启动时扫描入表；文件哈希变了自动降为「未验证」。
- 每个工作流登记成本地模型 `comfy/<slug>`（`Registry.add_spec`），出现在对应组件的 ModelPicker。**未验证的只能手动选**：不进自动路由、`alt_order`、兜底和「不满意换一个」（`capabilities` 那套过滤加一条）。
- 导入：校验 API 格式、拒绝素材板、已导入的 409；**猜绑定**（`LoadImage` → 首帧、正向 `CLIPTextEncode` → 提示词、采样器 `seed`、`EmptyLatent*` → 尺寸、`SaveVideo` / `VHS_VideoCombine` → 视频输出）；用了 DramaStudio 节点的免绑定。全部确认才能升级。
- 体检：`/object_info` 查缺的节点类（用 Manager 的节点表映射到节点包和版本）、加载器里的模型文件对照模型目录；装依赖复用安装器的步骤，**动手前先存快照**；试跑是 GPU 队列任务（示例输入、草稿尺寸、最短时长），进度走 `job.updated`。
- 档位规则照 M1 契约（推荐档不能改；升「我的」要绑定全确认 + 试跑通过 + 文件没变；改绑定降级）。装节点包后自动体检全部工作流，坏了提示回滚到装之前的快照。
- `model_call` 加 `workflow_id / workflow_sha256 / comfy_env_hash`（迁移 `0019`）和 `select_json`（按镜头选工作流的理由）。

### ComfyUI 适配器完整版（SPEC 6.4.1 / 6.4.7）

- WebSocket 进度（`/ws?clientId=`，`progress` / `executing` 消息 → `JobContext.progress`）；连不上回退到现在的 `/history` 轮询。
- 填 `first_frame / video_in / fps / seconds / dialogue_audio`（图片、音频都走 `/upload/image` 到 `input/dramastudio/`）；取 `video_out / audio_out` 结果，校验时长和尺寸。
- **H3 本地工作流** `workflows/h3-i2v/`：按 ComfyUI 官方 H3 模板展开成 API 格式 + `workflow.yaml`（首帧、参考图、台词音频、提示词、尺寸、帧率、时长、种子；草稿用 PLAN 写的 Turbo LoRA），推荐档；`providers.yaml` 的 `comfy/h3` 指过去。`selfhost/` 的旧格式不登记。真实节点名和参数第 14 步在本机核对。

### 视频组件 `vid`（SPEC 5、7.4、7.7）

- **物化**：分镜闸门确认后，每个镜头一个视频产物（owner `shot`，slot `video`）；`GET /episodes/{id}/shots` 的 `video_product_id` 从后端出（删掉 MSW 叠加）。
- **输入**：普通镜头用采纳的关键帧当首帧；连续镜头用上一镜**采纳 take 的尾帧**（真尾帧，M4 挪来），上一镜没采纳 → 409 `upstream_not_adopted`；锁定参考图按模型能收的张数；音频按 `audio_mode`（`tts` 喂台词音频，`native` 给锁定音色样本、说话人编号 S1/S2，`none` 不给）。时长 = 镜头时长（`pipeline/timing.py`），落到模型支持的区间。
- **提示词**：H3 官方六段式（`prompts/templates/vid/*.j2`），景别、运动、站位、动作行、台词、画面文字照关键帧那套写。
- **候选**：一次 N 条（`candidates`），每条裁掉开头 0.3 秒（新 `media/video.py`：探测、裁头、取尾帧、取封面帧；后期页的关闭开关是 M7 的事），文件带 `duration_s`、封面帧。
- **依赖和失效**：关键帧、台词音频、参考图、镜头结构字段变了 → 视频待更新；影响范围补视频行（`spec_aspect`、`shot_edit`、改台词）。
- **出终版**：候选卡「用 API 出终版」→ Regenerate-2K，草稿当 `video_in`，`stage=final`，父版本是草稿；`final_cost` 估价。
- **生成闸门** `takes`：每个镜头有采纳的 take 才能确认；进度「生成 n/9」从后端出。
- **本地超时兜底**：10 分钟没结果按兜底换 API，新版本 `origin=fallback` + `fallback_reason`，运行记录里记一笔（`notify: ask` 时先问）。

### API 适配器（SPEC 6.3）

- **MiniMax 视频**：H3（异步任务：上传文件 → 提交 → 指数退避轮询 → 下载）、Regenerate-2K、Context-IR（`llm_aux`，H3 API 的提示词按官方指南生成，走 `router.call()`）。H3 价格改国内站（DECISIONS 已定：768P ¥0.50/s、2K ¥0.80/s、重生成 ¥0.30/s，换算成美元存配置）。
- **Seedance 2.5**（火山方舟异步任务）。
- 模型 ID、参数、价格按官方文档核对，`verify: true` 的逐个核；单元测试用 httpx MockTransport，不触网。

### 生成页接口

- `GET/PUT /series/{id}/generate-rules`：映射到 `vid.candidates`、`fallback.qa_fail_n`、单镜头预算；质检阈值只读（M6 才用）。
- `GET /episodes/{id}/generate-log`：从任务、`model_call`、版本推出（出了候选、自动兜底、超预算等待确认……），不新建表。
- `POST /products/{id}/unadopt`、`PATCH /versions/{id} {rating}`。
- **最小 `GET /metrics/summary`**：只出表头要的「本集已花」等几项，让表头花费实时更新（M5 验收要），其余指标 M8。
- 质检是 M6：M5 的 take `qa` 为空、显示「未检查」；「推荐」先按评分、再按最新。`POST /versions/{id}/upscale`（2K 精修）是 M6，MSW 留着。

### 按镜头选工作流、可开关分支（SPEC 6.4.8）

- **规则表**放在「模型与兜底」同一处（剧集级配置覆盖 `vid.rules`）：条件（镜头类型、景别、有没有台词、`audio_mode`、有没有锁定参考图）→ 工作流，只能选推荐档和「我的工作流」。
- **LLM 建议**（可选，默认开关在规则表旁边）：一个小组件走 API 模型（默认 DeepSeek，配置可换），输入镜头摘要和候选工作流的能力，输出选哪个 + 理由；理由写进 `model_call.select_json`；Inspector 里能手动换。
- **分支**：`workflow.yaml` 加 `branches`（`controlnet / lora / upscale`，节点标题列表、默认开关）；关掉的分支在填图时按 `optional` 的规则拿掉；每个分支单独试跑；Inspector 按镜头开关（存 `shot.control_json`）。
- 这两块没有原型：按 M0.5 的风格做，截图给你看。
