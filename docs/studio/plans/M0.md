## 背景

ROADMAP 里第一个没勾完的里程碑是 **M0 地基**（一项都没勾）。现状：

- 仓库已经以上游 drama-series-agent 为初始代码（`upstream` remote 指向 binwu1/drama-series-agent，`LICENSE` 在），但**没有 `NOTICE`、没有 `UPSTREAM_NOTES.md`**。
- 后端：上游是 FastAPI（`cli.py:run_api_main` 里临时拼的 app，路由在 `api/routers/series.py`，41 个接口挂在 `/api`），状态全在文件里；`requires-python >=3.10`、setuptools 构建、**没有 uv.lock / ruff / mypy / tests/**。
- 已有可借鉴的：`utils/llm_client.py`（OpenAI SDK 封装、`list_inference_model_ids` 走 `GET /models`、`normalize_base_url`、429 提示）、`drama/event_bus.py`（进程内总线，无持久化）、`llm_presets.py`。
- 前端：上游 Hermes 聊天工作台（React 19 + Vite 8 + TS 6，hash 路由、手写 CSS、npm + oxlint），**没有 Tailwind / shadcn / i18n / Query / 测试**。
- 没有 `.github/`、`config/`（种子在 `docs/studio/seed/`）。
- 本机：uv 0.12 有，Python 3.12 需 uv 下载；Node 24 有，**pnpm 没装**（用 corepack 启用）。

目标：搭好 core / modelhub / 前端骨架，满足 M0 四条验收。

## 拆分成可单独提交的小步

每步结束 `uv run pytest`（及前端测试）都是绿的。

**分支与推送**：先 `git switch -c m0-foundation`；每个小步提交后马上 `git push -u origin m0-foundation`，并同时更新提交 `docs/studio/PROGRESS.md`。不推 main。里程碑做完 `gh pr create --base main`，描述用 `docs/studio/reports/M0.md`，Kelvin 看完再合并。

**节奏**：一个会话 3–4 个小步；收到上下文提醒就收尾，不硬撑到自动压缩。

### 3. core：配置 + 数据库
- `core/config.py`：Pydantic 模型解析 `providers.yaml` / `components.yaml`；`load_config()` = YAML 出厂默认 ⊕ `config_override` 表；`resolve(component, item)` 返回值 + 每个字段来源层级（project / component / item），M2 再接界面。
- `core/db.py`：SQLite（WAL、`foreign_keys=ON`、busy_timeout），async engine（aiosqlite）；数据目录 `DRAMA_HOME`，默认 `~/.drama-studio/`（`studio.db`、`blobs/`）。
- `core/models_db.py` + Alembic（`alembic/`，迁移 `0001_m0_core`）。**M0 只建本里程碑用到的表**：`job`、`model_call`（SPEC §10 全字段）、`config_override`、`provider_account`、`custom_model`、`event`（SSE 补发用，见步骤 5）。其余表（series、product…）在各自里程碑加迁移。
- 测试：YAML 解析、覆盖合并、来源层级、迁移 up/down。

### 4. core：内容哈希文件存储
- `core/storage.py`：`put_bytes / put_file / open / path_for`，路径 `blobs/sha256/ab/<hash>`，写临时文件后原子 rename，重复内容去重。测试：去重、原子性、Windows 路径。

### 5. core：事件总线 + SSE
- `core/events.py`：`publish(type, data)` 写 `event` 表（自增 id）后广播给 asyncio 订阅者；保留最近 N 条（默认 5000）。
- `api/v1/sse.py`：`GET /api/v1/events`，支持 `Last-Event-ID` 补发，15 s 心跳。
- 事件类型常量按 SPEC §9（M0 实际只发 `job.updated`、`cost.updated`、`toast`）。
- 测试：补发、多订阅者、断线重连。

### 6. core：持久化任务队列
- `core/jobs.py`：`enqueue / cancel / confirm`；状态机 queued → running → succeeded/failed/canceled（`waiting_confirm` 状态先建，预算逻辑 M2 接）；队列 `gpu`（并发 1）、`api:<provider>`（并发可配）、`cpu`（核数/2）；任务处理器按 `kind` 注册。
- 启动时 `running → queued`（attempt+1）实现续跑；每次状态变化发 `job.updated`。
- `api/v1/routes/jobs.py`：`GET /jobs`、`POST /jobs/{id}/cancel|confirm`。
- 测试：并发 1、取消、重启续跑（同进程模拟）。

### 7. modelhub：协议、注册表、Mock、router
- `modelhub/adapters/base.py`：`ModelAdapter` 协议、`Caps / Pricing / ModelRequest / ModelResult / Usage / Estimate / Health`（SPEC §6.1）。
- `modelhub/registry.py`：读 `providers.yaml` 生成适配器；`DRAMA_MOCK=1` 时全部换成 Mock（保留原 key 和单价，便于记账对得上）。

## 验收方式

1. `uv run pytest`、`uv run ruff check . && uv run mypy`、`pnpm -C web lint && pnpm -C web test` 全绿；推到 GitHub 后 Windows / Linux 两个 job 通过。
2. `uv run drama-studio dev` + `pnpm -C web dev`，浏览器里切中 / EN、点遍左侧导航 11 页。
3. 在 `/dev/jobs` 点“发起 Mock LLM 调用”：列表里看到 queued → running → succeeded 实时变化；`sqlite3 ~/.drama-studio/studio.db "select count(*) from model_call"` 多一行。
4. 发起几个任务后在排队时 Ctrl+C 后端再启动，任务继续跑完（e2e 测试自动覆盖 + 手动一次）。
5. 上下文监控自测（步骤 0）通过；里程碑做完写 `docs/studio/reports/M0.md`，`gh pr create --base main` 用它做描述，Windows CI 在 PR 上通过。
