## 设计要点

### 素材、素材分析（`assets` 组件）

**新表**
- `asset`：`id, series_id, kind, name, bible_id?, seed_json, retired`。
- `asset_use`：`asset_id, episode_id, scene_id, line_ids`，即出场矩阵。

**素材属于整部剧，按集分析**
- 产物 `asset_list` 挂在集上，采纳时物化。
- 物化**只增不删**：同一条素材按 `bible_id` 或「类别 + 名字」沿用 id，本集不再用到的只删掉本集的 `asset_use`，不会让别的集的素材退场。

**出场矩阵按规则算**
- 直接从剧本每行的 `character_id`、每场的 `location_id` 算出。
- 模型只做三件事：
  - 根据设定（外貌、补写的细节）写画面描述；
  - 从动作行里找道具和画面文字（逐字内容、推荐的字体和贴字方式）；
  - 每个说话的角色出一条音色。
- `asset_list` 只依赖本集说话人、场景、动作行的切片，改一句对白不会重跑分析。
- 没有说话人的旁白不配音，写进 DECISIONS。

**能改的字段都放在素材的产物上**
- 描述 = 提示词的意图层；画面文字的逐字内容、贴字方式、字体，音色来源，都放产物参数。
- `asset_list` 只在产物还没有版本时给初值。
- 「剧本里的描述变了」读的时候现算，不覆盖已经做过的素材。
- `img`、`text`、`voice` 产物不直接依赖设定或剧本。级联给素材槽位设了停止集：改剧本不会自动重画参考图，也不会解锁；配音照常级联。

**每条素材一个产物**

| 素材 / 对象 | 槽位 | 组件 |
|---|---|---|
| 角色、场景、道具 | `ref_image` | `img` |
| 角色锁定后补的视图 | `ref_views`（新） | `views` |
| 画面文字 | `text_image` | `text` |
| 音色 | `voice` | `voice` |
| 每行对白 / 旁白 | `line_audio` | `dub` |

- `views` 单独做一个组件：本地要用编辑模型，和出图的模型不同。
- 素材状态从产物算：已锁定 / 待选 / 待生成。

**示例种子**
- `seed_demo()` 补上 13 条素材，id 和 MSW 一致（`linwan` …），通过 `bible_id` 连到设定。
- 锁定状态照原型，7 / 13 已锁定。文件用 Mock 现生成。

### 候选、出终版、锁定、上传

**一次运行出一个版本**
- 候选放在 `files[]` 里，`role: candidate`，带 `idx`。
- 组件可以声明不自动采纳（`auto_adopt=False`），候选类组件都这样。
- 「选这个」记在产物上（`product.pick_json`），不放物化表，所以 `demo --reset` 或重建都不会丢。

**混合模式**
- 「重跑」走本地出 4 张草稿（`stage: draft`）。
- 选一张后，按钮「用 API 出终版」（带估价）：以这张草稿为参考，出 1 张终版（`stage: final`），`parent_version_id` 指向草稿。
- `RunService.start` 加 `where` 和 `params`（任务、来源版本和第几张、情绪覆盖）一路传到组件。

**上传**
- `POST /assets/{id}/upload`（图片）出一个 `origin: upload` 的版本，可以直接锁定，也可以当生成的参考。

**锁定**
- `ProductService.lock_pick()` 在一个事务里做完四件事：
  1. 出一个 `origin: pick` 的版本（新的来源类型，不算手改），只含选中的那一张（`role: ref`），沿用来源版本的模型、意图、依赖；
  2. 采纳，**不改当前版本**，这样候选网格还显示来源版本；
  3. 锁定；
  4. 写 `gate_decision`（`gate: assets`，`scope_id` 为素材 id）。
- 媒体槽位注册带文件 sha 的切片器，所以闸门里记的、下游依赖的都是这张图本身。

**整集素材闸门**
- 本集用到的素材全部锁定才能确认，确认时写 `gate_decision`（`scope_id` 为集 id）。
- `GateService` 的「哪些产物」改成可插拔：素材闸门按 `asset_use` 找。
- 重新打开某条素材时，包含它的已确认集一起重新打开。
- 进度里「素材」那一步改成真实计数。

**补视图**
- 角色锁定后自动跑 `views`：以锁定图为参考，出侧面、背面、表情各一张。
- 自动采纳，依赖锁定哈希。

### 多次调用的组件

**涉及的组件**
- 音色终版：设计 1 次 + 情绪变体 5 次；
- 画面文字：生成 + 每张 OCR；
- 补视图：3 张。

**规则**
- 组件内部调 router 时用 `fallback=False`，整个流程失败了再由组件统一兜底，不会出现半套变体来自另一家。
- 中间结果按请求缓存（像 `LlmCache` 那样），任务重试或重启续跑都不会重复花 $3。
- `estimate()` 把所有调用加起来。
- 每个用途用哪个模型写在配置里：`minimax/voice-design`、`minimax/speech-2.6-hd`（耳语）等。
- 价格解析 `extras`。音色设计的 $3 记在设计那一次调用上（MiniMax 实际在第一次合成时收，我们设计完马上就合成），写进 DECISIONS。

### 图像适配器

每家都按官方文档核对，`providers.yaml` 去掉 `verify`。

**请求**
- `ModelRequest(kind="image", prompt, params={n, aspect, size, refs, task})`。
- 宽高从 `output_spec` 算（硬规则 10），换成各家支持的尺寸。

| 适配器 | 模型和接口 | 要点 |
|---|---|---|
| `google.py` | `gemini-3-pro-image`，`generateContent` | 一次只出一张，n 张就并发 n 次；部分成功也照实记张数和花费；跳过 `thought` 部分 |
| `openai_images.py` | `gpt-image-2`；有参考图走 `/images/edits`，没有走 `/images/generations` | 9:16 用 `1152x2048` |
| `volcengine.py` | Seedream 5.0 | 档位实施时按价格定；必须带 `watermark: false`；用 `b64_json` |

**测试**：respx 假服务，不触网。

**账号**：媒体模型连到已有的供应商账号（`google_llm`、`openai_llm`、`volcengine`、`minimax_llm`），密钥沿用；「模型与兜底」页只补测试连接。

**ComfyUI 最小适配器**（`comfyui.py`）
- 流程：`/upload/image` → `/prompt` → 轮询 `/history`（不做 WebSocket 进度）→ `/view`。
- 超时调 `/interrupt` 并删掉排队中的任务。
- 按节点标题绑定（SPEC 6.4）。
- 两个工作流：
  - `workflows/qwen-image/`：Qwen-Image-2512，文生图；
  - `workflows/qwen-image-edit/`：Qwen-Image-Edit-2511，补视图、按参考编辑。
- 2511 只能编辑，所以要**多下约 20 GB** 的 2512。
- 每个版本都记 `workflow_id`、`workflow_sha256`、`comfy_env_hash`。

### 本地 Python 运行时

**`local_python` 适配器**
- 在 `~/.drama-studio/envs/<运行时>` 里起 worker 子进程，模型常驻。worker 脚本放在 `src/drama_series_agent/workers/`，不进 mypy。
- worker 协议：
  - 请求带 id；
  - 超时或取消就杀掉重启，避免读到上一个请求的回复；
  - 库的输出转到 stderr，stdout 只走 JSON；
  - 设 `PYTHONUTF8=1`、`HF_HUB_OFFLINE=1`；
  - stdin 关掉就退出。

**显存租约**（硬规则 8）
- 在适配器层面整个进程只有一把锁，不看任务在哪个队列：MiniMax 兜底到 IndexTTS 时，也要先拿到显存。
- 拿锁时让另一方让出：让 ComfyUI `/free`，或停掉 TTS worker。
- RapidOCR 只用 CPU，不拿锁。
- 超时 10 分钟走兜底。

**清单新增**

| 项 | 内容 |
|---|---|
| `rt_qwentts` | Python 3.12、torch cu130、`qwen-tts`、VoiceDesign 1.7B 和 12Hz 分词器；Windows 可能要装 SoX |
| `rt_indextts` | `index-tts` 锁 commit、Python 3.11、按它的锁定装 torch 2.8 cu128、不装 DeepSpeed；首次运行要下的辅助模型改由安装器预下载 |
| `rt_ocr` | `rapidocr` + `onnxruntime`，只用 CPU |
| `w_img_t2i` | Qwen-Image-2512 fp8 + Lightning LoRA |

- 安装器新增 `uv_sync` 步骤（按项目锁文件装）。
- 装完检查 `torch.version.cuda` 和 `sm_120`。
- 这些项都写上 `needs` / `requires_cuda`：没装（比如 Mac）时，能力过滤会把对应组件切到 API。音色本地试听切到 API 后，改用 MiniMax 设计的试听音频，只收字数费。
- IndexTTS 用 bilibili 模型协议（可商用、有条件），写进 DECISIONS。

### 画面文字（`text`）和 OCR

**「模型直接出字」**
- 出 4 张，每张都过 OCR。比对规则：NFKC 规范化、去掉空白，然后逐字比。
- 后端给每张候选标 `ocr_ok`；前端不再自己比。
- 不一致的标红，锁定返回 409 `ocr_mismatch`，除非带 `force`（界面上再确认一次）。
- 没装 OCR 时标「未检查」，不拦锁定。

**「后期贴字」**
- 出不带字的底图，用 OCR 确认底图上没有字。
- 前端按字体风格把字叠上去预览，真正合成放到 M7。

**OCR 本身**
- 组件 `ocr`（`qa/ocr.py`），走 router，本地 RapidOCR 记 $0。不做 API 兜底。
- Mock：Mock 图片把应有的文字写进 PNG 的 tEXt 块，Mock OCR 读出来；设置项可以强制返回不一致。

### 音色（`voice`）

按 ROADMAP 的流程：本地试听 → MiniMax 音色设计 → 情绪变体 → 统一响度 → 锁定。

**① 本地试听（免费）**
- 「重跑」用 Qwen3-TTS VoiceDesign 出 3 个草稿：描述加上偏低沉 / 更清亮 / 带一点沙哑三种倾向，每个都读这个角色的两句台词。

**② 出终版**
- 选一个，点「用 MiniMax 出终版」。
- 调 `/v1/voice_design`，拿到 `voice_id`。

**③ 情绪变体**
- 紧接着用 T2A 出 5 个情绪变体：平静、愤怒、哭腔、耳语、喊叫。这次合成会让 `voice_id` 转为永久（MiniMax 规定 7 天内不用就作废）。
- 估价 = $3 + 字数费，超过单次上限照常进「等你确认」。
- 情绪对应关系放在 `config/voice.yaml`：
  - 耳语用 2.6-hd（2.8 没有 whisper）；
  - 喊叫用 angry + 调高音量。

**④ 统一响度，⑤ 锁定**

**版本内容**
- 文件：锚点 + 5 个变体。
- payload：`{provider, voice_id, emotions}`。

**「本地」来源**
- 锚点就是 Qwen3-TTS 设计的那个，变体由 IndexTTS 按情绪文字出，全程免费。

**兜底**
- 改成本地 IndexTTS（和原型一致）。
- ElevenLabs 没有密钥，不在 M3 做。

### 台词配音（`dub`）和时长

**每行一个产物**
- 每行有说话人的对白 / 旁白一个 `line_audio`。
- 剧本重跑后退场的行，它的配音产物标 `retired`（产物加 `retired` 列），不算待更新，也不进进度和级联。
- 说话人的音色锁定了才能配；没锁时这一行显示「先锁定「周屿」的音色」。

**情绪**
- 语气 → 情绪用关键词表（`config/voice.yaml`）。
- 每行可以手动改，手动改的情绪记在产物参数上。

**调用**
- API：MiniMax T2A，传 `voice_id` 和情绪。
- 本地：IndexTTS，说话人用锚点，情绪参考用对应的变体。

**依赖**
- 新的剧本切片 `line:<id>`：文字、语气、角色。
- 音色的锁定哈希。
- 改台词或换音色后变「待更新」，「确认并同步」会自动重配。

**全集配音**
- `POST /episodes/{id}/dub`：先给总估价，再每行排一个 `product.run`。
- 事件不能刷屏：`product.updated` 只让对应的查询失效；配音产物不走 describer。

**统一处理**
- 48 kHz WAV，裁首尾静音，统一响度。
- 对白目标 −18 LUFS、−1.5 dBTP（放配置里），给 M7 的音乐和最终 −14 LUFS 留余量。
- 用 ffmpeg 处理（`imageio-ffmpeg` 已经有了），不加 pyloudnorm / scipy；SPEC 写的是 pyloudnorm，所以记进 DECISIONS。
- 短于 0.4 秒的按 RMS 估。
- 后端算好 64 段波形。
- 测试里可以跳过响度处理，加快速度。

**时长**（`pipeline/timing.py`）
- `line_seconds`：有配音用音频时长，没有用剧本估计。
- `scene_seconds`：场内各行相加。
- `shot_seconds(line_ids)`：音频总和，前面加 0.3 秒、后面加 0.2 秒；超过单段上限时建议拆。M4 用。

### 影响范围和级联

**流水线顺序**：剧本 → 素材清单 → 参考图 / 画面文字 / 音色 → 补视图 → 配音。

**`asset_unlock`、`asset_edit`**
- 这两种改动不产生新版本，比哈希找不到受影响的东西，所以由 planner 直接从依赖图列出受影响行。
- `asset_edit` 列出：
  - 本条会重新生成（附估价）；
  - 补视图；
  - 如果是音色：这个角色的所有配音；
  - 用到它的场（只提示，不改）；
  - 示例剧集里的镜头和关键帧行（由 MSW 叠加，M4 删）。

**`line_edit`**：带上「这一行的配音会重配」。

**影响行按槽位合并**：显示数量和合计花费，避免一下列出 60 行配音。
