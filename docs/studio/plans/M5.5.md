## 设计要点

### A. 镜头契约（分镜阶段生成，跟着镜头走）

- 新列 `shot.contract_json`（迁移 `0024`），新模块 `shots/contract.py`（Pydantic）：
  - `kind`：`performance / action / dialogue / insert`；`beats`：动作预算（insert 0 = 只许微动；performance 1–2；dialogue 跟着台词；action 按片长 2–4）。
  - `start` / `end`：镜头开始、结束时人和道具的状态（`[{subject, state}]`，门开 / 关、伞在哪只手）。连续镜头下一镜的 `start` 默认取上一镜的 `end`。
  - `props`：`[{asset_id, state}]`，状态是**摆出来的**（便利贴有字、边角湿），除非这个镜头的动作就是这个变化。
  - `delivery`：每个说话行 `dialogue / offscreen / inner`。
- 分镜规划模板（`prompts/templates/plan/default.j2`）和 `PlannedShot` 加这些字段；`ops.normalize` 缺的按规则补（`kind` 用现在 `vid.gather` 的判断搬过来；`delivery` 从剧本 `type` / `tone` 推：`vo` + OS → inner，其余 `vo` → offscreen；`end` 缺就等于 `start`）。
- 契约进分镜规划的 `shot:<id>` 切片：改契约 → 关键帧、视频待更新；编辑走 `PATCH /shots/{id}`（已确认的走影响范围 `shot_edit`），和现有字段一样。
- **关键帧画起始状态**（M5 遗留「关键帧是概括画面」）：`kf` 编译层写 `start` 和道具状态、按道具尺寸写相对人物的比例。
- **视频侧**：`vid.gather` 读契约的 `kind` / `delivery`（不再现算）；改写系统提示词第 8 条按 `kind` 给动作预算（第 15j 步「2–4 个动作」只给 action）；新增：同一状态变化只发生一次、不许撤销重做，犹豫要演出来；`h3_format` 加撤销重做的检查词（`again`、`closes it … opens`）；`inner` 嘴闭着（现在按 `vo` 做的改成按契约）。

### B. 道具：尺寸、实拍质感、带上自己的字

- 设定抽取模板给道具加 `size`、`material`、`wear`（长柄伞约 90 cm、尼龙、木柄磨旧）；素材 `seed_json` 带过去，素材页可改。
- 道具参考图提示词：实拍、用过、在环境里（15o 已去白底，这里补尺寸和新旧）；道具锁定后**另出一张和人物同框的比例参考**（新槽位 `ref_scale`，组件 `img` 的编辑模型，拿锁定的道具图 + 相关角色图），关键帧取参考时紧跟在道具图后面。
- **有字的道具，字是道具的一部分**：素材分析把「写在某个道具上的字」并进那个道具（道具的 `settings` 多 `text`：逐字内容、笔、手写风格），道具图直接画写了字的那张；OCR 检查跑在这种道具的候选上（和文字素材一样标不一致，只提示）。屏幕、招牌这类独立文字照旧是文字素材。示例剧 `txt1` 并进 `note`。

### C. 检查（只提示、不挡）

- **分镜检查**：规则（`shots/check.py`，读时现算、不花钱）：同一状态变化出现两次 / 撤销重做、动作超预算、相邻两个非连续镜头同场同机位同景别（像回放）、`inner` 的镜头写了张嘴说话。LLM 检查（新路由组件 `plancheck`，kind `llm`，默认 DeepSeek）：读剧本 + 契约，补规则看不出的（动作重复、犹豫写成机械重复）。结果存成每集一个产物（owner episode，slot `shot_check`），按规划切片哈希判断过时；`model_call` 照记。
- **关键帧检查**（新路由组件 `kfcheck`，kind `vlm`，默认 Gemini 3.1 Flash-Lite，本地 Qwen3-VL 可选）：每张候选出完后查：道具比例、带字道具的字在不在 / 是不是手写（再跑 OCR 对逐字内容）、起始状态对不对、`inner` 嘴闭着。结果写版本 `qa_json`（按候选），估价并进关键帧估价。
- **take 检查**（新路由组件 `takecheck`，kind `vlm`）：抽 6 帧拼图 + 已有的定格 / 切点 / 台词位置（`payload.window`、`cuts`）：重复动作、凭空的物理事件（倒水、爆开）、字变了、`inner` 时嘴在动。写 take 的 `qa_json`；take 墙原来的「未检查」换成这几项的结果（其余质检项 M6）。

### D. 图片来源与编辑

所有结果都是新的候选版本（父版本是来源），照旧挑选、锁定、换回；新操作各是一个路由组件（`components.yaml` 选模型，本地 / API、估价、`model_call` 照旧）。

- **`media/image.py`**（新）：探测宽高、按矩形裁切并缩放到目标尺寸（FFmpeg `crop` + `scale`）、抽帧拼图。
- **上传关键帧**：`POST /shots/{id}/keyframe/upload`（文件 + 裁切矩形；没给就居中）→ 按成片画幅裁切、缩到交付尺寸，`origin=upload`、一张候选、自动选中；小于草稿档报 `low_res` 警告（只提示）。确认镜头时直接锁定（现有逻辑：单张锁整版），视频首帧就是它。「用 API 出终版」允许以上传版本为来源。
- **素材**：
  - 多参考图：新槽位 `ref_more`（一个版本多张，每张 `purpose`：正脸 / 服装 / 发型 / 姿势 / 其他）；上传、删一张都出新版本。关键帧取参考：素材主图后按用途接上，不超过 `max_refs`。
  - 六视图单张替换：`POST /products/{id}/views/{view}`（上传或重画这一张）→ 复制其余 5 张出新版本。
  - 手动新建素材：`POST /series/{id}/assets {kind, name, description}`，`asset.manual`（迁移 `0024`），重新分析不退场；建好产物，能加进镜头参考。
- **镜头参考图**：新槽位 `shot_refs`（owner shot，每张 `purpose`：构图 / 姿势 / 光线 / 风格）；**剧的风格板** `style_board`（owner series）。关键帧取参考顺序：素材 → 镜头参考 → 风格，取到 `max_refs`，提示词里注明「图 n 只参考构图」；都进关键帧的依赖哈希。
- **以这张为底重画**（新组件 `redraw`，kind `image`）：`POST /versions/{id}/redraw {idx, prompt, strength}`，适用关键帧、参考图、六视图单张、上传的图。本地 Klein（`denoise` = 改动幅度，默认）/ Qwen-Image-Edit；API nano-banana-2.1 / gpt-image-2（没有数值强度，幅度写进提示词）。
- **局部修复**（新组件 `inpaint`）：前端画布涂遮罩 + 提示词，`POST /versions/{id}/inpaint`（遮罩 PNG）。本地新工作流 `workflows/klein-inpaint`（Klein + 遮罩，本机核对）；API gpt-image-2 带遮罩编辑（按官方文档核对，`verify: true`）。
- **图片超分**（新组件 `iup`）：本地新工作流 `workflows/seedvr2-img`（SeedVR2 图片模式，本机先验证），关键帧放大到交付尺寸、参考图长边 2048。只有本地；没装时按钮灰掉写原因。
- **声音克隆**（最后一步）：音色来源 `clone`：上传 ≥ 10 秒样本 + 勾「本人授权」；MiniMax 克隆（价格、接口按官方文档核对）/ 本地 IndexTTS 直接用参考音频。原型 Assets 有文案。
