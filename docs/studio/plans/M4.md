## Kelvin 已定（2026-10-21）

1. **镜头时长**：
   - 有对白的镜头 = 台词音频 + 前 0.3 秒 + 后 0.2 秒（来源「音频」）。可以手动加长，但不能短于音频。
   - 没对白的镜头用分镜规划给的初值（来源「手动」）。
   - 画外音叠在动作镜头上：取「动作镜头的时长」和「画外音 + 留白」中长的（示例 1-06 仍是 5 秒）。
2. **不做预演配音 `pv`**：
   - 动态分镜直接放素材页配好的台词配音；
   - 还没配音的句子静音、只显示字幕，旁边给「去配音」；
   - Inspector 只有「分镜规划」「关键帧」两个组件。
3. **分镜规划不跟着「确认并同步」自动重做**：
   - 剧本加删行、改结构后，分镜规划标「待更新」，影响范围里写明；由用户在分镜页点「重跑」再采纳。
   - 只改了某一行动作描写：只有拍这一行的镜头的关键帧待更新。
   - 改对白措辞不影响分镜：只会重配音，时长跟着变。
4. **本机真跑 + 真实冒烟（上限 $1）**：
   - 本机：ComfyUI 用 Qwen-Image-Edit 拿锁定的角色图、场景图出关键帧草稿（多张参考图）；
   - 冒烟：DeepSeek 跑第 1 集分镜规划，Nano Banana Pro 出 1 张关键帧终版。

## 设计要点

### 分镜规划（`plan` 组件）和镜头表

**产物**：每集一个 `shot_plan`（owner 是集，组件 `plan`）。`ensure_series_products` 会自动建好。payload：

```
{shots: [{id, scene_id, line_ids, shot_type, framing, camera_move, duration_s, intent, summary,
          asset_ids, tail_from, audio_mode, blocking, difficulty}]}
```

**模型做什么**：每场拆镜，给出：
- 拍哪几行、镜头类型、景别、机位运动；
- 画面描述（关键帧提示词的种子）、一句话摘要；
- 参考素材（只能从本集素材里选）、声音做法、站位、难度；
- 没对白的镜头的时长初值。

**规则做什么**（确定性的后处理，和 M3 出场矩阵一样）：
- **覆盖校验**：对白和旁白各属于且只属于一个镜头；动作行至少一个镜头拍到；场内顺序不乱。不过就带着错误重试一次（沿用结构化输出的重试）。
- **类型**：每场第一个镜头不能是「连续动作」。
- **接哪个镜头的尾帧**：「连续动作」默认接同一场里前一个非插入镜头。插入镜头 = 没有人物的特写，比如便利贴、手机。所以 1-08 接 1-06，不是 1-07。
- **参考素材**：只保留本集 `asset_use` 里有的。
- **站位**：模型没给就按规则摆人物、道具、地标，机位按景别放。
- **id**：重跑时按「同一场 + 拍的行有重叠」，再按顺序，沿用已采纳版本里的 id（M2 的做法）。

**依赖**：
- 新的剧本切片 `shots`：场的地点和时段；每行的 id、类型、说话人；非对白行的文字。所以改对白措辞不会让分镜规划变旧。
- 素材清单的 id、名字、类别。

**不进级联**：`Component` 加开关 `cascade_rerun`（默认开），`plan` 关掉。原因：重做会盖掉手改和镜头确认（Kelvin 定第 3 项）。

**物化**：
- 采纳时写 `shot` 表：按 id upsert、重排序号、版本里没有了的标 `retired`。
- 每个非连续镜头 `ensure` 一个关键帧产物（owner `shot`，slot `keyframe`，组件 `kf`）；镜头退场或改成连续动作时，它的关键帧产物标 `retired`。

**`shot` 表**（迁移 `0018`）：
- id, episode_id, scene_id, idx, shot_type, framing, camera_move, duration_s（规划或手填的值，不含音频）, intent（种子）, summary；
- line_ids, asset_ids, tail_from, blocking_json, audio_mode, difficulty, control_json（M5 用）, retired, version_id。
- SPEC 的 `size`、`character_ids` / `prop_ids` 改用前端契约已有的 `framing`、`asset_ids`，记进 DECISIONS。
- 镜头号「1-04」读的时候现算（集序号 + 本集第几个）。

**用户改**（`PATCH /shots/{id}`）：
- 结构和设定字段（类型、景别、运动、时长、参考素材、声音做法、站位）：从当前版本出一个 `origin=edit` 的 `shot_plan` 版本并采纳（M2 剧本行的做法）。
- **画面描述 = 关键帧产物提示词的意图层**（M3「描述 = 意图层」的做法）：写到关键帧产物的提示词上，镜头表里的 `intent` 只是种子。重跑分镜后种子变了，标 `seed_changed`。
- `keyframe_pick` 写关键帧产物的 `pick_json`；`confirmed` 见下面「确认镜头」。
- 手填时长短于音频：422 `duration_below_audio {min_s}`；传 `null` 恢复成自动。

**拆分、合并**：
- `POST /shots/{id}/split {after_line_id?}`：
  - 按行切开，默认从中间切；
  - 只有一行时：动作行两个镜头都拍它，对白留在前一个、后一个当反应镜头（没有台词，时长手填 2 秒）；
  - 前一个保留原来的关键帧，后一个新建一个空的关键帧产物。
- `POST /shots/{id}/merge`：
  - 和同一场的下一个镜头合并，行取并集；
  - 保留前一个的关键帧，后一个的关键帧产物退场。
- 都出 `edit` 版本。拆或合已确认的镜头，走影响范围 `shot_edit`。

### 时长（Kelvin 定第 1 项）

- `timing.py` 加 `shot_duration(...)`，返回 `{seconds, source: audio|manual, min_s, split}`，按上面的规则算，用 M3 的 `line_seconds`（配了音用音频长度，没配用剧本估计）和 `shot_seconds`。
- **读的时候现算、不存版本**：重配音后时长自动跟着变，不产生新版本。
- **单段上限**取当前 `vid` 路由的模型 `caps.duration_s` 的上限（H3 是 15 秒），超过就提示拆镜。
- **示例**：没配音时 1-04 按剧本估计 4 秒，算出 4.5 秒，整集 34.5 秒（原型 34 秒）；配音后按 Mock 音频变。记进 DECISIONS。

### 关键帧（`kf` 组件）

**和 `img` 一样**：
- `MediaComponent`，`auto_adopt=False`，一次出 3 张候选（`components.yaml`）；
- 混合模式：本地草稿 → 选一张 →「用 API 出终版」出 1 张，`parent_version_id` 是草稿（M3 第 5 项的做法，原型「v2 · 3 张终版」不照做）。

**尺寸**：从成片规格算（`frame_size`），提示词写画幅（「竖屏 9:16 构图」）。

**编译的上下文块**：
- 景别、机位运动；
- 站位：俯视图转成文字，比如「林晚在画面中间偏右、靠后，面朝门；机位在正前方」；
- 场景标题和时段；
- 这个镜头拍的剧本动作行；
- 参考图；
- 画面文字：「模型出字」写出逐字内容，「后期贴字」写「留出位置、不要出字」。

**参考图只用已锁定的**：
- 按 角色 → 场景 → 道具 → 画面文字 的顺序，取到模型的 `max_refs` 为止（本地 3 张）；
- 没锁定的不传，编译层里写「未锁定，没传：旧黑发圈」。

**依赖**：
- 镜头切片 `shot:<id>`：类型、景别、运动、站位、参考素材，不含时长和声音做法；
- 拍的动作行的 `line:<id>`；
- 用到的参考图的锁定哈希。

另外：关键帧版本的画幅 ≠ 现在的画幅，也算待更新（改画幅不经过产物）。

**规格锁定**：`on_adopt("keyframe")` 在同一个事务里，`locked_at` 为空就写上（SPEC 13.3）。

**带字的镜头**：默认模型等 P0 中文文字实测的结论再定；现在可以在这个镜头的运行设置里手动换 GPT Image 2（单个镜头的覆盖）。

### 确认镜头、分镜闸门

**「确认这个镜头」**（`PATCH {confirmed: true}`）：
- 非连续镜头：要有关键帧版本，做 `lock_pick`（当前版本 + 选中的那张；终版只有一张就锁整版）。
- 连续动作：要求它接的那个镜头存在。
- 都写一条 `gate_decision`（gate `shot`，scope 是镜头 id），哈希记镜头切片和关键帧的锁定哈希。

**取消确认**：
- 解锁关键帧，写 `reopen`；
- 这一集的分镜闸门已确认时一起重新打开（M3「解锁素材重新打开集」的做法）。

**「待更新」**：已确认，但镜头切片的哈希变了（重新采纳了分镜规划），或者关键帧变旧了（参考图换了、动作行改了、画幅改了）。

**分镜闸门**（gate `storyboard`，scope 是集）：
- 前提：本集镜头都已确认、都不是待更新，否则 409 `shots_not_confirmed {count, labels}`；
- 确认时锁定已采纳的 `shot_plan`；重新打开时解锁。
- 实现上是 `GATES` 加一项，再加一个可插拔的前提检查。

**进度**：
- 分镜一步 = 已确认 / 镜头数，外加待更新数；
- `EpisodeOut.shot_count` 换成真实值。

### 影响范围

- **`shot_edit`**（新）：改已确认的镜头，或改闸门锁着的分镜。
  - 列出的行：这个镜头的关键帧要重画（改的是影响关键帧的字段时；本地草稿免费，出终版约 $x）、这个镜头要重新确认、分镜闸门重新打开。
  - 「只改这里」= 取消确认后写入；「确认并同步」= 再给这个镜头重出关键帧候选（候选类，选好再确认）；「撤销」。
- **`spec_aspect`**（从 MSW 挪到后端）：
  - 列出的行：`keyframes_redraw {count, shots}`，带估价（重出草稿免费，出终版约 $0.14 × 张数）；按旧画幅出的场景参考图（可选，只提示）；视频到 M5 才有，数量是 0 不列。
  - 「只改这里」写画幅、取消确认受影响的镜头、重开闸门；「确认并同步」再给这些镜头重出草稿。
  - `PUT …/spec?confirmed_impact=` 真的校验 id（SPEC 13.3 留的 TODO）。
- **`asset_edit` / `asset_unlock`**：多列「镜头 1-01、1-04… 共 n 个」和它们的关键帧（待更新；已确认的要重新确认）。
- **`line_edit`**：
  - 动作行：拍它的镜头的关键帧待更新；
  - 对白：「镜头 1-04 的时长跟着配音变」（只提示）；
  - 加删行：「分镜规划 · 待更新（不自动重做）」。
- `PIPELINE_ORDER` / `_STEP` 加上 `shot_plan`、`keyframe`，归到分镜这一步，待更新数才算得进进度。
