## 设计要点

### A. 连续性账本（`shots/ledger.py`，迁移 `0025` 建 `continuity_state`）

- 一行一个镜头：`shot_id, version_id`（分镜规划的哪一版）、`json`：`characters[{asset_id, position（左 / 中 / 右 + 近 / 远，来自 blocking）, facing, holding[prop asset_id], outfit}]`、`props[{asset_id, state, where}]`、`time{time_of_day, clock?}`。
- **按规则推、不另调 LLM**：同一场按镜头顺序滚动：站位读 `blocking_json`，手里的道具和道具状态读契约的 `start` / `end` / `props`（上一镜的 `end` 延续到下一镜，直到某镜改变它），服装读角色素材的描述（场里没写换装就延续），时间读场的 `time_of_day`，画面文字道具的时钟类内容（1-07 的 23:52）进 `clock`。
- 物化：和 `shot` 一样在分镜规划采纳时写（改契约、站位都会出新的规划版本 → 重新物化），能从版本重建（有测试）。账本进 `shot:<id>` 切片的派生里，不改哈希规则（输入都已在切片里）。
- 谁读：关键帧和视频的编译上下文（SPEC 8 本来就列了账本）、质检的视觉检查（C）、分镜页镜头详情里只读的「连续性」一节（改法 = 改契约 / 站位 / 素材描述，点了跳过去）。

### B. 质检工具（本地，`runtimes/qa` 新 uv 环境，worker `workers/worker_qa.py`）

- **一律 CPU**（onnxruntime / CTranslate2 int8 / torch CPU）：不进 GPU 队列、不和 H3 抢显存（硬规则 8），Mac 上也能跑。一条 5 秒 take 预计 < 1 分钟；慢了再加 GPU 选项。
- 模型（实现时按官方仓库核对许可和下载地址，`providers.yaml` 标 `verify: true`；清单 `rt_qa` 装环境、`w_qa` 下权重，可选项失败只记录）：
  - 人脸 `local/auraface`：YuNet 检人脸（OpenCV Zoo）+ AuraFace 嵌入（Apache 2.0；InsightFace 预训练权重是非商用，不用）。每秒抽 2 帧，每张脸配到这个镜头最像的角色，和锁定参考图（主图 + 正脸多参考）比余弦，取每个角色的中位数，镜头分 = 最低的那个角色。
  - 口型 `local/syncnet`：syncnet_python 的 v2 权重（MIT），人脸用 YuNet 裁嘴部区域；只给有 `dialogue` 的镜头，输出置信度（阈值 6 的量纲就是它）。
  - 台词 `local/whisper-large-v3`（faster-whisper，已在 providers 里）：识别 take 的音轨，和契约里 `dialogue` 的台词比字错率（NFKC、去标点空白）；`inner` / `offscreen` 不算。M7 字幕对齐复用。
  - 说话人 `local/campplus`（3D-Speaker CAM++，中文训练，Apache 2.0）：take 里每句台词的片段和说话人锁定音色的锚点比相似度；新阈值 `speaker_sim`（先 0.6，本机校准）。
  - 画面文字：现有 RapidOCR，每秒 1 帧，和镜头预期文字（文字素材 + 带字道具）逐字比；字只出现在部分帧时只比读到字的帧。
- 都是 `router.call()`（组件 `qa`、model key 按工具），写 `model_call`（$0、记时长）。**Mock**：每个工具一个 Mock，默认按文件哈希给稳定的通过分；示例的坏 take 在 `params.mock_qa` 里写好要给的分（只有 Mock 认），测试同理。

### C. 质检任务（`pipeline/qa.py`，组件 `qa`）

- **每条新 take 出完自动入队一个质检任务**（queue `cpu`，视觉检查那一步走 API 队列；不挡出片队列）。也可在 take 卡上「重新质检」。
- 各项：face / lipsync / asr / speaker / ocr / vlm；不适用的 `ok: null`（没对白不查口型和字错率、没字不查 OCR、没人脸不查人脸）。**vlm = 现在的 take 检查 + 账本**：`takecheck` 并进 `qa`（「模型与兜底」页的「自动质检」那一行就是原型里的「质检模型」，默认沿用 take 检查的 Gemini 3.1 Flash-Lite；`takecheck` 的覆盖配置迁到 `qa`），拼图提问里加账本：左右站位、手里拿的、服装、时段光线。
- 结果写 take 版本的 `qa_json = {checks, score, thresholds, ran_at}`、`qa_pass`（**不改内容哈希**，和打分一样只是元数据），同时回写生成这条 take 的那次 `model_call.qa_scores_json / qa_pass`。总分 = 各项归一化后的平均（`ok: null` 不算），「推荐」= 通过的里总分最高的（SPEC 4.2）。
- 阈值**按剧可调**：生成规则 `thresholds` 改成可写（`app_setting` 照旧只存改过的），每项可关；`components.yaml` 是默认值。
- SSE：质检写完发 `version.qa`，前端刷新这一镜。

### D. 不达标自动重跑和兜底（`pipeline/qa_policy.py`）

- **去掉 `vid.run` 里 take 的运行内重画**（9e-5）：每条 take 都留下、质检照常，没过的在墙上可见（原型「质检没过，已自动重跑」）。关键帧的 `kfcheck` 运行内重画不动。
- 一个镜头**最新一批里没有一条通过**才动作：
  1. 只有 lipsync 没过 → 自动口型修复（E2），本地直接跑，API 先估价。
  2. 其余情况：这个镜头连续没过的次数 < `qa_retry_max` → 同一模型再出一条，origin `auto_qa_rerun`，没过的项写进提示词（沿用 `redraw.failed_text`）。
  3. 到了 `qa_retry_max` → 按 `vid` 路由的兜底换下一个模型，origin `fallback`、`fallback_reason=qa_fail`、`model_call.is_fallback`；`notify: ask` 时进 `waiting_confirm`。
  4. 兜底也没过 → 停下，运行记录写「需要你看」，不再花钱。
- 每次入队前 `estimate()`，本地免费照跑；API 加上这个镜头已花会超 `shot_cap_usd` → `waiting_confirm`（硬规则 6）。手动「重跑 / 换一个」会把连续次数清零。
- 运行记录加 `take_pass / take_fail`（已有占位）、`auto_rerun`、`qa_fallback`、`qa_stop`、`auto_lip`。采纳没过的 take 照常可以，toast 写「有 n 项质检没过，你选择了保留」（原型文案）。

### E. 精修三件（结果都是这个镜头视频产物的新版本，父版本 = 原 take，自动质检；来源已采纳且新版本通过 → 自动采纳，闸门锁定时只做候选）

1. **2K 精修**（组件 `up`）：`POST /versions/{id}/upscale` 接 take。本地 SeedVR2 → 兜底 FlashVSR（工作流已有，尺寸读 `output_spec`，硬规则 10），API `minimax/h3-regenerate-2k` 只给本地 H3 草稿（有 `raw` + `params.request`），Topaz 没适配器、不可选。origin `upscale`、`stage=final`。按钮显示估价的钱和耗时；删 MSW `handlers/generate.ts`。
2. **口型修复**（组件 `lip`）：`POST /versions/{id}/lipsync`。用这个镜头的台词配音轨（`media/audio.py:dialogue_track`，原生同步的镜头也换成配音轨 = PLAN 模式 C）。API `sync/lipsync-2-pro`（新适配器，接口和价格按 sync.so 官方文档核对）；本地 LatentSync 1.6（Apache 2.0，`runtimes/latentsync` + worker，GPU 租约、并发 1、先 `/free` ComfyUI，清单 `rt_latentsync` / `w_latentsync`）；`infinitetalk` 仍不可用。origin `lipsync`。Mac 只有 API。
3. **视频局部修复**（新组件 `vinpaint`，kind video）：前端在 take 的首帧上涂遮罩 + 写提示词 → `POST /versions/{id}/inpaint`（和图片局部修复同一个接口，按版本类型分；遮罩 PNG，整条 take 用同一块区域）。本地 Wan VACE 工作流 `workflows/vace-inpaint`（ComfyUI 原生 VACE 节点，遮罩外原样贴回）。**先本机验证**：选哪个 VACE 权重、步数、768p 一条 5 秒的耗时和显存，结论记 DECISIONS；验证不过就停下来问 Kelvin。只有本地，没装时按钮灰掉写原因。origin `inpaint`。

### F. 前端

- 生成页 TakeWall：质检块接真实数据，加 `speaker` 一项，vlm 一项展开就是 M5.5 的检查条目和拼图；「重新质检」；「局部修复」变菜单：口型修复（显示价格 / 本地）、局部修复（遮罩画布复用 M5.5 的 `InpaintDialog`，画在首帧上）；2K 精修接后端；采纳没过的 take 的提示。
- 规则面板：阈值可改（现在是只读文案），每项开关；状态卡「自动质检」、运行记录的新条目。
- 分镜页镜头详情：「连续性」只读一节（站位、手里的、服装、时间），每行「去改」。
- 素材页小修（M5.5 遗留）：克隆模式的产物条不再写「音色候选 3 个」。
- 原型没有的三处（账本一节、阈值编辑、局部修复菜单 + 视频遮罩弹窗）先出线框草图 `docs/studio/prototype/m6/`，和 M5.5 一样，Kelvin 看过再做前端。
- i18n 两种语言同时加；做完一块删一块 MSW（`finishing.ts` 的质检 / 精修示例产物），挪成 `web/src/test/fakes/` 的测试假后端。

## 风险

- 本地工具的分数量纲和模型有关，阈值必须本机校准（5c）；VLM 误报照旧，只要能报出第十七轮的问题。
- 视频局部修复（VACE）效果和显存未知，8a 验证不过就和 Kelvin 商量缩范围。
- LatentSync 多人同框质量下降（PLAN 已写）；只修说话人那张脸，不行就走 API。
- 质检全在 CPU：如果一条 take 超过 2 分钟，改成 GPU 档并走 GPU 队列（记 DECISIONS）。
