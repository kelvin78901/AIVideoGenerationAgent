# M4 分镜与动态分镜 · 里程碑报告

> 分支 `m4-storyboard`（从合并 PR #5 后的 main fb08576 切出），计划 [`docs/studio/plans/M4.md`](../plans/M4.md)。写给 Kelvin，也作为 PR 描述。

## 做了什么

M4 把「剧本 → 分镜规划 → 关键帧候选 → 选定 / 出终版 → 确认镜头 → 动态分镜预演 → 分镜闸门」这一段在后端做通了：

- Mock 下整条流程都能走，示例第 1 集 9 个镜头、7 张关键帧（1-08、1-09 接尾帧）。
- 分镜页、表格视图、拆分合并、动态分镜全部接真实接口，对应的 MSW 示例数据删掉了；生成页、后期页的示例数据改读后端的镜头。
- 你的 5090 上用 Qwen-Image-Edit 拿锁定的角色图、场景图真出了关键帧；DeepSeek 真跑了分镜规划，关键帧真出了一张 API 终版（Seedream 兜底，见下）。

**框架（第 1 步）**

- 新表 `shot`（迁移 `0018`）：分镜规划已采纳版本的物化表，和剧本行一样按 id 沿用、退场不删。
- 镜头时长按你定的第 1 项：有对白 = 台词音频 + 前 0.3 秒 + 后 0.2 秒，可以手动加长、不能短于音频；没对白用规划的初值；画外音叠在动作镜头上取长的。读的时候现算，重配音不产生新版本。超过视频单段上限（H3 15 秒）提示拆镜。
- 组件新开关 `cascade_rerun`：分镜规划不跟着「确认并同步」自动重做（你定的第 3 项）。

**分镜规划（第 2 步）**

- 组件 `plan`：模型每场拆镜；能确定修好的问题用规则直接修（没拍到的行补镜头、每场第一个不是连续动作、连续动作接前面最近的非插入镜头、参考素材只留本集的、没给站位按素材摆），不为此多花一次钱重试。
- 重跑时镜头 id 沿用（同一场 + 拍的行有重叠），所以已确认的镜头和关键帧不会因为重跑丢掉。
- 依赖只看结构：改对白措辞、改动作描写都不会让分镜规划变旧（改动作描写只让拍这一行的镜头的关键帧待更新）。
- 接口：`GET /episodes/{id}/shots`、`PATCH /shots/{id}`、`POST /shots/{id}/split|merge`。

**关键帧（第 3 步）**

- 组件 `kf`：一次 3 张候选，本地草稿 → 选一张 →「用 API 出终版」1 张。
- 参考图只传已锁定的，按角色 → 场景 → 道具 → 画面文字取到模型能收的张数；没传的在提示词里点名。
- 提示词写画幅、景别、机位运动、场景、站位（俯视图转成文字）、拍的动作行、画面文字的做法。
- 「确认这个镜头」锁定选中的关键帧并写闸门记录；第一个镜头确认时锁定成片规格。

**分镜闸门、进度、影响范围（第 4 步）**

- 「去生成视频」要求 9 个镜头都确认、都不是待更新，否则提示还差哪几个。
- 改已确认的镜头走影响范围 `shot_edit`；改画幅的影响范围从 MSW 挪到后端：列出 7 张关键帧（9 个镜头要重新确认），估价约 $0.94。
- 改已锁定的素材会列出用到它的镜头（改林晚列出 6 个）；改对白提示「时长跟着配音变」。

**分镜页接后端（第 5–7 步）**

- 关键帧显示真图、能放大、选这个、出终版、确认；Inspector 的单镜头覆盖按镜头 id。
- 「分镜板 / 表格」切换（`?view=table`，选中的镜头写进 `?shot=`），表格里直接改类型、景别、运动、时长；拆分（多行时选切点）、和下一个合并。
- 时长写明来源（按台词音频 / 手动 / 按分镜规划）、最短多少、「恢复按音频」、超过 15 秒建议拆镜。
- 动态分镜：按镜头时长播放，配素材页配好的台词配音（不做预演配音，你定的第 2 项），没配音的句子只有字幕并给「去配音」；连续动作先用来源镜头的关键帧；空格键、点时间条跳转；「安全区」开关叠在预演和关键帧候选上，比例读后端。

**Mock 端到端（第 8 步）**：后端 `tests/e2e/test_script_to_storyboard.py` 从新剧集走到分镜闸门；Playwright 新项目 `m4` 在浏览器里走预演、出终版、逐个确认、确认闸门。

**本机真跑（第 9 步）和真实冒烟（第 10 步）**：见下面「本机和真实冒烟」。

**收尾（第 11 步）**：SPEC 补了 M4 的实际做法（4.1、4.2、5.1、9.1、13.3），ROADMAP 勾选。

## 和计划不一样的地方

**你中途定的**：

- 真实冒烟里 Nano Banana Pro 那张终版不补跑，兜底的 Seedream 算通过（第 10 步）。

**工程上的改动**（理由见 DECISIONS 各步）：

- 分镜规划的模型回答用规则补齐，不为覆盖问题重试（计划写的是「带着错误重试一次」）。
- 剧本切片 `shots` 不含任何文字（计划写的是含非对白行的文字），和你定的第 3 项对上：改动作描写只让拍它的镜头的关键帧待更新。
- 表 `shot` 的列用前端契约的 `framing`、`asset_ids`，不用 SPEC 原来的 `size`、`character_ids` / `prop_ids`；时长分 `duration_s`（规划）和 `manual_s`（手填）两列。
- `PUT …/spec?confirmed_impact=` 的校验从第 4 步挪到第 5 步（和删 MSW 的改画幅一起，不然中间那几个提交的 e2e 会断）。
- 关键帧没有锁定参考图时换 Qwen-Image，从第 3 步挪到第 9 步（Mock 下看不出区别）；做法是组件新钩子 `model_for`，换成哪个模型写在 `components.yaml` 里。
- 第 9 步顺手修了站位文字和单幅画面约束（上面说的两个问题）。

**按计划不在 M4 做**（DECISIONS「M4 计划」）：预演配音 `pv`（不做）、连续性账本（M6）、真正的尾帧（M5）、带字镜头默认走 GPT Image 2（等 P0 中文文字实测）、动态分镜导出 MP4、H3 换国内价（M5）、3D 场景、生成页 `?shot=` 用镜头号的不一致（M5）。

## 遗留问题

- **拼图、陌生人、风衣污渍**（你看图时指出的）：做了对照实验（`m4-local-smoke.txt` 末尾）。拼图的诱因是参考图提示词里「给后面每个镜头当参考」，改成「一张单幅写实照片」后楼道 8/8 单幅；没有角色的镜头加「这个镜头里没有人物」后，冒出陌生人从 5/6 降到 1/6；风衣污渍是 1-01 剧本里「湿了半边」这几个字（换成「被雨淋湿」就没有了）。
- **草稿的构图比较单一**：4 步加速下同一提示词的几张很像，挑的余地小。官方 50 步更多样，但每张慢约 20 倍。
- **Nano Banana Pro 出终版会改构图**：提示词要求照着草稿，它把背景换成了参考图里的楼道。
- **Seedream 这次慢**：带 3 张参考图出 1 张用了近 4 分钟（M3 时十几秒），下次真跑再看是不是偶发。
- **画面文字和描述打架**：1-07 的画面文字是「后期贴字」，但画面描述里写了 23:52，模型照样画出了时间。等带字镜头的默认做法定了再处理。
- **分镜规划的真实效果**：DeepSeek 把画外音单独拆成一个镜头（原型叠在动作镜头上），两种都说得通，现在由用户在分镜页合并。
- **关键帧默认模型的切换还没做完**：本地草稿 FLUX 3 Klein、API 终版 Nano Banana 2.1。新加的两个模型和工作流已经提交，可以手动选；改默认要同时让「没装 Klein 的机器」草稿换回 Qwen-Image-Edit 而不是走收费 API，还要更新示例机器、兼容表和前端快照，下个会话做完再刷新这份报告。
- `confirmed_impact` 记在内存里（最近 100 条），后端重启后之前的预览 id 就不认了，要重新预览一次。

1. **重启后端**，再跑一次 `demo --reset`（`uv run --no-sync python -m drama_series_agent.studio_cli demo --reset`）。M4 加了迁移 `0018`、示例分镜和关键帧、很多新接口；分镜页现在完全读后端，不重启的话前端会报「接口返回的数据和约定不符」。
