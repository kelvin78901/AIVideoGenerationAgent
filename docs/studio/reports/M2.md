# M2 小说 → 剧本 · 里程碑报告

> 分支 `m2-novel-script`（从 main 切出），计划 [`docs/studio/plans/M2.md`](../plans/M2.md)。写给 Kelvin，也作为 PR 描述。

## 做了什么

M2 让「导入小说 → 补全 → 设定提取 → 分集规划 → 剧本化」在后端真的跑起来：Mock 下整条流程都能走，真实模型统一经过 `router.call()`。小说页、剧本页、模型与兜底页和几个共用组件都接上了真实接口，对应的 MSW 示例数据已删掉。除了计划里的内容，还做了你 2026-10-19 定的几项：设定读已采纳的补写、小说和剧本都能手改、改已确认的内容后「确认并同步」、小说逐段编辑。2026-10-20 又加了一项：没分集时也能确认小说。最后用你的 DeepSeek 密钥跑了真实冒烟：第一章花了 $0.0078，整本花了 $0.0530。

**产物和版本（第 1 步）**

- 表 `product`、`product_version`（只追加）、`dependency`、`gate_decision`（迁移 `0007`）。
- **版本是唯一真相**。设定、补全、分集、节拍、场、剧本行这些表都是已采纳版本的物化结果，随时能从版本重建（有测试）。
- id 在出版本时就定下来；重跑时内容能对上的沿用原来的 id。
- 「待更新」按依赖切片的哈希现算，不存标志：改了再撤销，会自动变回不旧。
- 接口：`GET /products`、`GET /products/{id}`、`set-current`、`adopt`、`lock`、`unlock`。

**配置接口 + 模型与兜底页（第 2 步）**

- 四个预设和全局默认（迁移 `0008`）、组件级覆盖、恢复成预设、密钥（存钥匙串）、兜底方式、备选顺序。
- 各页 Inspector 的运行设置也读后端。

**组件框架、提示词、Mock（第 3 步）**

- 组件协议和 `product.run` 任务。
- 提示词分两层：Jinja2 模板只写指令（编译层），原文、设定这些数据块发送时再拼上。
- 结构化输出用 Pydantic 校验，不合格就带着错误重问一次。
- 长小说按上下文分块；分块结果缓存（`llm_cache`，迁移 `0009`），重试或重启续跑不重复花钱。
- Mock 按（组件，任务）给出应答：示例小说返回固定的示例 JSON，其他小说用确定性规则生成。

**预算和确认（第 4 步）**

- 入队前估价；超过单次上限或本集剩余预算，任务进「等你确认」，确认的金额记在任务上（迁移 `0010`）。
- 兜底换到更贵的模型时，超出确认金额就失败，不悄悄多花。
- 前端有全局的「要你点头」弹窗。

**剧集和导入小说（第 5 步）**

- 顶栏剧名改成菜单：剧集列表 +「新建剧集…」。新建后先到成片规格页，再到小说页。
- 导入 .txt / .docx：先识别章节，勾选改编权后才导入。
- 小说本身也是一个产物（迁移 `0011`）：重新导入 = 替换，旧文本留在历史里。
- 示例小说《雨停之前》扩到 3 章、3006 字。

**设定提取（第 6 步）、补全（第 7 步）、逐段编辑（第 7b 步）**

- 设定提取：
  - 读原文 + 已采纳的补写；
  - 按名字和别名合并条目，「疑似同一人」让模型判断后作为合并建议；
  - 设定卡：编辑、冻结、拆出别名；点卡片高亮原文（迁移 `0012`）。
- 补全：
  - 每条建议锚定到原文段落；
  - 采纳、忽略、恢复、按要求重写；
  - 修订视图（原文 / 采纳后 / 对比）（迁移 `0013`）。
- 逐段编辑：原文里点一段直接改，能插入、删除段落，能改章节标题。

**分集规划（第 8 步）**

- 节拍看板：一列一集，节拍可拖到别的集；上面一条全剧情绪曲线（迁移 `0014`）。
- 能改集名、钩子、卡点、预计时长；本集预算是设置，改它不出新版本。

**剧本化（第 9 步）**

- 每集只读本集的节拍、引用的段落、这些段落上的补写和本集用到的设定（迁移 `0015`）。
- 来自补写的剧本行，出处标「补写」。
- 能改一行、改场标题，也能让模型重写一行或一场（同样查预算）。
- 三向溯源：剧本行 ↔ 原文段落 ↔ 镜头（镜头那一向的数据到 M4 才有）。

**闸门、影响范围、确认并同步（第 10 步）**

- 「确认原文」「确认剧本」：锁定已采纳的版本；可以重新打开。
- 改已确认的内容（八种改动）先做影响预览，三个选项：
  - 「确认并同步 · 预计 $x」：下游按流水线顺序自动重跑并采纳，旧版本都留在历史里；被锁的先重新打开闸门。同步中途重启也会接着跑。
  - 「只改这里，下游标待更新」
  - 「撤销」

**收尾的几步（第 11–13 步）**

- 删掉上游旧界面 `/legacy`，后端不再挂上游的 `/api/series/*`；上游代码留在仓库里。
- 端到端：pytest 起真实后端进程走完整条流程；Playwright 在界面上走同一条流程。另加一轮关掉示例数据的检查（`VITE_DEMO_DATA=0`），专门找前后端字段对不上的地方，**一处都没找到**。11 页亮 / 暗重新截图。
- 第 12d 步：没分集时也能「确认原文，生成剧本」，确认后进剧本页做分集规划。
- 第 13 步：按官方文档核对了 DeepSeek、Kimi、通义千问的模型 id；写了冒烟脚本；用真实 DeepSeek 跑通了。

## 和计划不一样的地方

- **你中途定的四项**（2026-10-19）：设定读已采纳补写；手动编辑 + 确认并同步（硬规则 5 因此改了：只有你在弹窗里确认的改动才会自动替换版本）；小说逐段编辑（新增第 7b 步）；示例小说加长到约 3000 字。
- **第 12d 步**（2026-10-20 你定的）：没分集时也能确认小说。为此新加接口 `GET /series/{id}/progress`。
- **计划外的接口**：
  - `PATCH /scenes/{id}`：重写场标题要用；
  - `POST /bible/merge`：合并、「不是同一个」、拆出别名；
  - `PUT /series/{id}/novel/chapters/{idx}`：逐段编辑；
  - `GET /series/{id}/progress`。
  - 另外 `GET /series/{id}/bible` 的返回从数组改成了对象。SPEC 9.1 已同步。
- **默认关掉模型的「思考模式」**（第 13 步）：DeepSeek、Kimi、千问这些模型默认都开着思考模式。思考过程按输出 token 计费，还会占用输出长度上限，而估价没算这部分。所以在 `providers.yaml` 里给每个模型加了一个请求参数，默认关掉。要开的话改配置就行，不用改代码。
- **后端不再挂上游的 `/api/series/*`**：这些接口直接调模型、不经过 `router.call()`，唯一用到它们的 `/legacy` 页也已删掉。
- **Mock 和 DeepSeek 分出的集数不同**：示例数据按原型分成 3 集；DeepSeek 跑整本分成 5 集。
- 第 10 步拆成了 10a / 10b / 10c，第 12 步拆成了 12a / 12b / 12c，内容没变。

## 新加的工程决定（DECISIONS.md）

M2 的计划和每一步各有一条，日期 2026-10-19 / 20：计划；第 1–9 步（含 7b）；你定的「设定读已采纳的补写」「手动编辑和自动同步」；第 10、11、12、12d、13 步。主要包括：

- 版本是唯一真相，其余表是物化结果；
- 依赖按切片算哈希，「待更新」现算；
- 小说也是一个产物；
- 两个闸门各管什么，影响预览在事务里试写再回滚；
- 「确认并同步」不建表，按流水线顺序走、每个产物最多跑两次；
- 关掉示例数据跑 e2e；
- 默认关思考、冒烟脚本。

## 遗留问题

- **长小说的设定提取可能超出输出上限**：整本 3000 字的设定输出了约 3000 token，组件上限是 4000。长小说的单块输入最多能到 2 万 token 左右，输出可能超过上限，JSON 被截断后会重问一次，仍然失败。建议在 M3 前改：按输出量限制分块大小，或者调高上限。
- **剧本质量**（看整本冒烟的输出）：
  - 第 5 集只有 1 场；
  - 补全给外卖员加了一句粗口；
  - 第 2 集鞋子前后不一致（帆布鞋 / 拖鞋）。
  - 这些都是提示词和模型的问题，不是程序错误。要不要调提示词、要不要试思考模式，你看完输出再定。
- **其他供应商还没核对模型 id**：火山、智谱、MiniMax、Google、OpenAI、OpenRouter 仍标着 `verify: true`，用到时再核对。Kimi 的价格没核对，官方价格页的表格读不出来。Kimi 和千问都没有密钥，没真调过。
- 顶栏「本集花费」仍是示例数据（`/metrics/summary` 在 M8）；「本集预算用完后暂停所有 API 任务」的全局开关没做（超过本集剩余的新任务已经会先问你）。
- 计划里定为「不在 M2 做」的：自定义模型、人物关系图、「用 TTS 试读一场」、提示词黑名单、改画幅的真实影响范围。
- Playwright 收尾时后端会打印 aiosqlite「Task was destroyed but it is pending」，不影响结果，还没查。
