# M0.5 界面先行 · 里程碑报告

> 分支 `m0.5-ui`（从 `m0-foundation` 切出，M0 合并后 rebase 到 main），计划 [`docs/studio/plans/M0.5.md`](../plans/M0.5.md)。写给 Kelvin，也作为 PR 描述。

## 做了什么

11 个页面按原型做成了能点的 React 页面，用《雨停之前》第 1 集的示例数据跑起来。后端还没有的 `/api/v1` 接口由浏览器里的 MSW 返回示例数据；已经有的（任务、供应商、健康检查、SSE）直接走后端。**M1 起各里程碑的界面条目改成「接真实接口、删掉对应的 MSW handler」，界面不重写。**

**数据层（第 1 步）**

- 每个接口都有 zod schema（`web/src/api/schemas/`），响应在运行时校验，对不上报 `bad_response`，不会悄悄显示错的东西。
- MSW 示例库（`web/src/mocks/`）：内存里一份可改的数据库，handler 按里程碑登记在 `mocks/handlers/index.ts` 的表里——实现一个接口就删一行。
- 示例数据的响应带 `x-drama-demo` 头，顶栏出现「示例数据」标记；`VITE_DEMO_DATA=0` 可整个关掉。
- 演示事件（重跑完成、安装进度、同步进度……）和真实 SSE 走同一个分发器，页面分不出来源。

**共用组件（第 3–5 步）**：设计 token（五种状态色、亮 / 暗两套、图表色）、shadcn 基础件补齐；StatusBadge、PageHeader、MediaThumb、EmptyState、QueryState 等小件；8 个正式组件 **RunBar、Inspector、ModelPicker、PromptEditor、VersionHistory、ImpactDialog、GateButton、CostBadge**，都有 Vitest 测试，在 `/dev/components` 能看到各种状态（ModelPicker、PromptEditor、VersionHistory 在 Inspector 的三个标签页里）。顶栏接了数据：剧名 · 集名、规格标签、GPU、本集花费 / 预算；左侧导航有进度徽标。

**页面（第 6–17 步）**

## 怎么验证

```powershell
# 一键起前后端（Mock 模式），浏览器打开 http://127.0.0.1:5173
powershell -ExecutionPolicy Bypass -File .\start.ps1

# 全部检查
pnpm -C web test; pnpm -C web lint; pnpm -C web typecheck; pnpm -C web format:check
uv run pytest
pnpm -C web e2e        # Playwright 冒烟，自己起 Mock 后端 8765 + Vite 5183，不影响正在跑的 start.ps1
pnpm -C web shots      # 重截 docs/studio/reports/ui/ 下的 22 张图

# 关掉示例数据：没实现的接口显示「加载失败」或「没有可显示的内容」，不出现假数据
$env:VITE_DEMO_DATA = "0"; pnpm -C web dev
```

建议手动走一遍：

1. 小说页采纳一条建议 → 「重跑」→ 1.4 秒后历史多一版。
2. 剧本页改一段已确认的剧本 → 弹影响范围 → 选「只标记」→ 导航出现「待更新」。
3. 素材页解锁一项 → 影响范围；生成页按 ← → 选候选、A 采纳。
4. 成片规格页改画幅 → 页内影响范围。
5. 首次启动页「开始检测」→「全选」→ 安装，看 SageAttention 失败后重试 / 跳过。
6. 右上角切 EN 和暗色，各页再看一遍。

**示例数据里的关键数字**（和原型一致，都写在测试里）：本集 $8.94 / 预计 $13.35 / 预算 $15；42 次调用、1 次失败；9 个镜头、34 秒；素材 7/13、分镜 3/9、采纳 3/9；质检 6/10。

## 测试和 CI 结果

- Vitest：**164 passed**（23 个文件），含 i18n 中英 key 一致性检查
- pytest：**118 passed**（后端只改了 SSE 断开的 bug 和 `DRAMA_WEB_ORIGINS`）
- Playwright 冒烟：**13 passed**（11 页能打开、没有控制台错误、能切语言；示例数据标记；示例数据开着时真实任务仍经 SSE 实时更新）
- ESLint、tsc（strict）、Prettier、ruff、mypy 全过
- CI：Linux 每次 push 跑全部检查 + Playwright 冒烟；Windows 在开 PR 时跑（不跑 e2e）。第 18 步第一次在 CI 上跑时，首次启动页的完整安装测试在 CI 上要 10 秒，超过了等待上限。原因不是等待时间：每一步只等 2 ms，但约 120 个进度事件每个都让整页重渲染一次。现在演示步骤的延迟在测试里设成 0 时，所有步骤在同一个任务里跑完（`mocks/events.ts:repeatDemo`），页面只渲染最终状态；这个用例在 CI 上原来要 10.4 秒，现在整个 Setup 测试文件（7 个用例）5.3 秒，本机这个用例 0.6 秒；本机前端全量测试从 17 秒降到 9 秒，测试里不再需要放宽等待。同步页同样处理。
- **PR 上的 CI**：Linux 通过（pytest 118、Vitest 164、Playwright 冒烟 13）；Windows 通过（pytest 118、Vitest 164）。

## 和计划不一样的地方

- **`VITE_DEMO_DATA=0` 核对后多修了几处**（计划里只写了「核对」）：
  - 很多查询要用上游的结果当 key（比如分集 id 来自 `/series`），上游失败时它们永远是 disabled，页面会一直转圈。现在显示中性提示「没有可显示的内容：它依赖的数据没加载到」和「重试」。
  - 顶栏本集花费没拿到时写「—」，原来写 $0；模型页拿不到主机信息时写「未知」，原来写「没有可用的显卡」「ComfyUI 已连接」；素材页清单没加载到时不显示「已锁定 0 / 0」；同步页素材板标题不再默认写「第 1 集」；404 有了中文说明。
- **数据看板没做「今天」范围**：SPEC 11 有，原型没有（只有「第 1 集 / 全剧」），已记 DECISIONS，M8 再定。
- **补了 `sfx`（音效）组件和产物 slot**：原型后期页有，SPEC 的组件表没有；M7 实现时补进 components.yaml。

## 新加的 DECISIONS

「2026-10-14 · M0.5 界面先行」一节共 45 条，主要是三类：

- **做法**：接口契约用 zod；MSW 默认开启；演示事件和真实 SSE 同一个分发器；界面文字和内容分开（枚举返回 code，前端翻译）；改已确认的内容一律「先预览、后落盘」；Playwright 自带服务；Vitest / Playwright 固定时区 `Asia/Shanghai`；i18n key 不能有冒号；暗色图表色换成校验过的一组。
- **每页的接口细节**（第 4–17 步各一条）：SPEC 没写的字段、补的读接口、状态码。已整理进 SPEC 9.1（标 ⁺ 的是新增），字段以 `web/src/api/schemas/` 为准。
- **产品层面的小取舍**（都在对照表里也写了）：分集卡用路由切换、后期页没有闸门按钮、「导入 .txt / .docx」先置灰、生成页支持 `?shot=` 等。

「2026-10-15 · M0.5 收尾」：上面说的缺数据显示规则；Playwright 冒烟只在 Linux CI 跑。

## 遗留问题

- **示例里的操作刷新页面就复原**：数据只在浏览器内存里（计划里已知）。
- Playwright 冒烟收尾时后端会打印 aiosqlite「Task was destroyed but it is pending」，不影响结果，还没查。
- 冒烟只验证「能打开、能切语言、没有报错」，不做截图像素比对；视觉回归靠人看对照表。
- `VITE_DEMO_DATA=0` 的核对是手动跑的临时脚本，没有进 CI（要再起一个关掉示例数据的 Vite，CI 时间翻倍，等真实接口多了再考虑）。
- 同步页素材板默认选中的节点 `kf103` 写在页面里（示例数据的节点 id），M9 接真实素材板时改成「第一个关键帧」。
