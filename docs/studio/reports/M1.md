# M1 首次启动 + 成片规格 · 里程碑报告

> 分支 `m1-setup-spec`（从 main 切出），计划 [`docs/studio/plans/M1.md`](../plans/M1.md)。写给 Kelvin，也作为 PR 描述。

## 做了什么

M1 把「首次启动」「成片规格」两页从浏览器里的示例数据换成了真实后端：后端真的能检测这台机器、按清单安装（Mock 下模拟），成片规格存进数据库，尺寸和兼容表由后端算。2026-10-18 起按你的要求又加了四块：识别你已经装的 ComfyUI、改它之前先确认并存快照、「工作流库」界面（示例数据），以及在你的 5090 上真装节点包和权重；真装时你提出的安装进度和预计用时也做了。

**成片规格（第 1–3 步）**

- 表 `series`、`output_spec`（迁移 `0002`）；平台预设和默认规格在 `config/spec.yaml`；`spec/dims.py` 是唯一算尺寸的地方；`spec/compat.py` 按当前路由给每个模型判 原生支持 / 需要转换 / 不支持。
- 接口：`GET /series/{id}`、`GET/PUT /series/{id}/spec`（锁定后改画幅返回 409 `spec_locked`，在影响范围里选了处理方式才写）、`GET /spec/presets`、`GET /series/{id}/spec/compat`。
- Mock 启动时库里没有剧集就建示例剧集《雨停之前》（`studio/demo.py:seed_demo()`），所以删掉 MSW 的剧集和规格 handler 后其他页面照常能用。
- 成片规格页和顶栏规格标签改走真实后端。

**检测这台机器（第 4a、4b、4c 步）**

- 清单 `config/setup-manifest.yaml`：解析、平台覆盖、`fix` / `if_missing`、依赖成环和重复 id 校验。
- 14 种检测器，只通过 `Probe` 碰机器：`RealProbe` 只读，`FakeProbe` 读原型的两台示例机器（PC、Mac）。
- 扫描是一个后台任务，每检测完一项推一条 SSE；结果存 `machine_profile`（迁移 `0003`）。
- **识别你的 ComfyUI**（只读）：
  - 读 ComfyUI Desktop 2 的安装记录，找正在运行的实例（先试 8188，再试 8000）；
  - 识别版本、commit、Python、PyTorch、ComfyUI-Manager；
  - 节点包按 git、Registry、手动三种来源记版本；
  - 模型目录（含 `extra_model_paths.yaml`）和文件。
  - 结果存 `comfy_env`（迁移 `0004`），接口 `GET /comfy/env`。

**安装（第 5a、5b、5c 步）**

- 一次安装是一个后台任务：
  - 按依赖顺序装，失败的项可以重试或跳过；依赖失败时，依赖它的项自动跳过；
  - 后端重启后接着装，已经装好的不重装；
  - 需要你点头的（管理员权限、单项超过 10 GB、改你的 ComfyUI）先弹确认。
- 真实安装器支持 7 种步骤，每步幂等，装之前先检测一遍；镜像有自动、官方、国内三种。
- **改你的 ComfyUI 之前**：
  1. 先列改动清单：每项从哪个版本到哪个版本、来源、大小。
  2. 你确认后，先用 ComfyUI-Manager 存快照，再动手；存不成快照，这些项就不装。
  3. 「你的 ComfyUI」面板里可以一键回滚。
  - 快照记在 `comfy_snapshot`（迁移 `0005`）。

**按机器过滤路由（第 6 步）**：`providers.yaml` 的本地模型写明要哪些清单项、要不要 CUDA。解析路由时，这台机器跑不了的本地模型自动绕开。所以 Mac 上视频、关键帧、超分自动走 API，兼容表也跟着变。

**界面（第 7、7b 步）**

- 首次启动页接真实后端，删掉对应的 MSW handler：
  - 新加安装确认弹窗和「你的 ComfyUI」面板（识别结果、快照、回滚）；
  - 会改 ComfyUI 的项默认不勾。
- 左侧导航「环境与安装」，徽标显示「缺 N 项」；打开 `/` 而且从没扫描过时跳到这一页。
- 前端测试的假后端改用真实后端导出的数据（`web/src/test/data/setup.json`）。后端回答一变，pytest 就失败，两边不会再分叉。
- **工作流库**放在「模型与兜底」页最下面，用示例数据，设计稿你审过：
  - 列表和筛选；
  - 导入：拖进 JSON，或从 ComfyUI 的工作流列表里选；
  - 确认绑定、体检、装依赖（复用安装确认弹窗）、试跑、改档。

**清单补齐和真装（第 8、8b 步）**

- 版本全部锁定：
  - ComfyUI v0.42.1，最低要求 0.35.0；
  - H3、Fun ControlNet、SeedVR2 是 ComfyUI 自带的节点：按节点类或 ComfyUI 版本判断，不再是安装项；
  - ComfyUI-Manager 4.2.2 用 pip 装（ComfyUI 0.4x 的官方装法）；
  - VHS、FlashVSR 锁 commit；PyTorch 用 cu130 源；国内 GitHub 走 gh-proxy。
- 权重用你选的版本：五项各锁 Hugging Face revision 和 sha256，共约 110 GB，放进 ComfyUI 的默认模型目录（Desktop 的共享目录）。
- **在你的 5090 上真装了**：
  - 装好的有 VHS、FlashVSR，以及权重 H3（49.3 GB）、文本编码器（15.7 GB）、SeedVR2（8.8 GB）、IndexTTS-2.5（5.5 GB），sha256 全部对上。
  - 第一次回滚被 ComfyUI-Manager 在 Windows 上的 bug 卡住；绕开以后第二次回滚成功，之后又把两个节点包装了回去。
  - SageAttention 在 Windows 上改用预编译包加 triton-windows，在 5090 上跑通；ComfyUI 现在带 `--use-sage-attention` 启动。

**安装进度和预计用时（第 8c 步）**

- **下载**：
  - 64 MB 分块，多连接动态分段；连接数按实测速度从 1 个往上加，最多 8 个；
  - 按块续传；Windows 上用稀疏文件。
- **进度**：
  - 下载中的项显示「已下 / 总大小 · 速度 · 剩余」，算 sha256 时显示「校验中…」；
  - 整体进度按用时加权；
  - 安装按钮旁和确认弹窗里写「约 N GB，预计 M 分钟」，按这台机器测到的下载速度算。
- 安装位置在程序文件夹里时给黄色警告：这次真装时 IndexTTS 就下进了仓库。
- **回滚之后由下一次扫描核对**：显示「已回滚」「等重启 ComfyUI」或「回滚没完成」，没完成时列出还不一样的地方。原来点了就算回滚成功，但真装时第一次回滚其实失败了。

**收尾（第 9 步）**：SPEC 补上 M1 的实际做法（表、接口、清单字段、下载、回滚核对、路由过滤、导航）；ROADMAP 的 M1 全部勾完；修了一个偶发失败的单元测试（见「测试和 CI 结果」）；本报告。

## 新加的 DECISIONS

M1 一共 24 节，2026-10-15 到 2026-10-19，基本每个小步一节。主要是：

- **计划阶段你定的四件事**：
  - ComfyUI 先用已有的；
  - 清单先补运行环境和节点；
  - 导航入口「环境与安装」；
  - Mock 下检测和安装都是模拟的。
- **做法**：
  - 检测和安装分别通过 `Probe` / `StepRunner`，各有真实和示例两种实现；
  - 一次安装是一个后台任务；
  - 能力过滤在合并完各层覆盖之后做；
  - 快照接口按 Manager 4.2.2 源码核对；
  - 前端假后端用真实后端导出的数据。
- **真装得出的**：
  - 回滚前先建 `.disabled`，绕开 Manager 在 Windows 上的 bug；
  - 装完再检测一次，检测不到报 `not_detected`；
  - SageAttention 在 Windows 上用预编译包，triton-windows 按 PyTorch 版本选（`by_torch`）；
  - 权重放 ComfyUI 的默认模型目录。
- **你定的产品取舍**：
  - 2026-10-18「ComfyUI 与工作流库」；
  - 「按镜头选工作流；拼节点做 beta」（写进 SPEC 6.4.8，M5 做）。

## 遗留问题

- Eagle、达芬奇的检测标着 `verify: true`：你的机器上没装，没实测过。
- 本地 LLM 的清单项还是 TODO（等 P0）；DramaStudio 节点包显示「还没发布」（源码 M5 才有）。
- 回滚的已知限制：
  - 快照之后多装的 pip 包不会被卸载（Manager 只补齐快照里有的）；
  - 停用的节点包留在 `custom_nodes/.disabled`；
  - 要你自己重启 ComfyUI 才生效。
- 国内镜像的 GitHub 代理 gh-proxy 是第三方服务，不能用时选「官方源」。
- 多连接下载只在测试和小文件上验证过；第 8c 步之后还没真装过大文件，加连接到底能快多少还不知道。
- 改画幅的 `confirmed_impact` 只检查不为空；影响范围在 M4 之前仍是示例数据。
- 工作流库只有界面（示例数据），后端在 M5。
- 卸载只记录了 `installed_item`，没有按钮（原型里没有）。
- 新建剧集（`POST /series`）在 M2，和导入小说一起做。
- M0.5 遗留：Playwright 冒烟收尾时后端会打印 aiosqlite「Task was destroyed but it is pending」和几条 SSE 连接的 `CancelledError`，不影响结果，之前的 CI 日志里也有。e2e 在 2026-10-18 偶发失败过一次，之后连跑 17 次没复现。
