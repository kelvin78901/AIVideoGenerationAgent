## 和计划不一样的地方

1. **上游界面搬家提前到第 10 步**：上游代码过不了 TypeScript strict，与其放松新代码的检查，不如先挪进 `src/legacy/` 并整文件跳过类型检查；第 11b 步只剩挂 `/legacy` 路由和 CSS 作用域。
2. **兜底只跳一次**：失败后换到 `fallback.to`（为空用 `alt_order` 的下一个），再失败就报错，不沿着备选列表一路试，避免坏天气里花费成倍增加。
3. **Mock 是默认模式**：不设 `DRAMA_MOCK` 也走 Mock，`DRAMA_MOCK=0` 才调真实模型。
4. **开发接口多了 `where` 参数**：`POST /api/v1/dev/llm-test` 可以选 `local`，走 gpu 队列，用来测试「并发 1 + 重启续跑」。
5. **上游的 `scripts/run_api.py` 也改成用 app factory**（计划里只写了 `cli.py`），否则 `start.ps1` 启动的还是旧 app。
6. **顶栏的花费暂时从调用记录汇总**（M8 换成 `/metrics/summary`），GPU 状态从任务列表里数 gpu 队列。
7. **新增 `.gitattributes`（统一 LF）**，并把 `docs/` 排除出 ruff（新版 ruff 会改写 Markdown 里的 Python 代码块）。
8. **CI 的 action 版本**：checkout / setup-node 用 `@v7`；setup-uv 没有浮动的大版本标签，锁定 `v10.2.0`。

## 新加的 DECISIONS（2026-10-14）

进度交接机制 · M0 工具链 · M0 数据库与配置 · M0 任务队列 · M0 模型层 · M0 前端工具链，共 6 组，详见 [`DECISIONS.md`](../DECISIONS.md)。要点：

- ruff / mypy 先只检查新代码，改到哪个上游文件再纳入。
- `job` 表多 `result_json`、`depends_on_json` 两列；新增 `event` 表做 SSE 补发。
- 只有明确可重试的错误才自动重试；崩溃后续跑也算一次尝试，用完次数判 `interrupted`。
- 每次模型调用尝试都写一行 `model_call`，失败的 `billed=false`。
- 密钥查找顺序：钥匙串 → 环境变量 → `.env`；测试里不会读到你机器上的 `.env`。
- pnpm 替换 npm、ESLint 替换 oxlint；JSON 文件没法写注释，改过的上游 JSON 由 NOTICE 统一说明。
