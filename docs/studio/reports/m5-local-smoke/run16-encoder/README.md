# 第十六轮：H3 文本编码器 nvfp4 对 int8（第 15l 步，2026-11-09）

调研报告（`../../m5-h3-research.md` 第 6 节第 5 条）说 4 位的 `nvfp4_awq` 编码器可能念错中文台词、细小动作变糊，建议换 `int8_convrot`（27.1 GB，从 hf-mirror 下载，SHA-256 和 Hugging Face 的 LFS 记录一致）。这一轮在第十一轮数据的副本上，1-04（有台词「……周屿？」）和 1-08（没台词，开门）各出两条：种子和第十一轮第 1 条一样，提示词一样（改写和看图走缓存，两条的提示词 sha 相同），只在本进程里换 `Text encoder` 节点的 `clip_name`（产品没动）。

```
DRAMA_LIVE=1 uv run --no-sync python scripts/smoke/encoder_ab.py --home <第十一轮的数据目录> --shots 1-04 --only nvfp4
DRAMA_LIVE=1 uv run --no-sync python scripts/smoke/encoder_ab.py --home x --work <副本> --shots 1-08 --only nvfp4   # 再 --only int8 各一次
```

## 定下来的

**默认照旧用 nvfp4**：int8 在这两个镜头上没有看得出、量得出的好处，却多 11 GB 下载、文本编码时多占内存（这台机器在出片时内存已经紧到后台任务被回收）。int8 文件留在本机，以后有更长的中文台词、怀疑发音问题时可以拿 `encoder_ab.py` 再比。局限：1-04 的台词只有两个字，长台词的发音这一轮没测到。
